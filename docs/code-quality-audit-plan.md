## 1. 怎么用这份文档

### 1.1 角色与节奏

| 角色 | 职责 | 投入 |
| --- | --- | --- |
| 审核负责人 | 排期、维护 §9.3 看板、裁决优先级、汇总阶段报告 | 全程，约 0.2 FTE |
| 架构审核人 | 范围 A + F 的技术部分 | 第 1–2 周 |
| 构建/交付审核人 | 范围 B | 第 1 周 |
| 前端审核人（UI） | 范围 C + D 的 T1 页面 | 第 2–5 周 |
| 领域审核人（按模块分工） | 范围 E 的对应能力域 + D 的 T2 页面 | 第 3–6 周 |
| QA | 复现、回归锚点、e2e 补测 | 全程 |

节奏建议：每日 15 分钟站会只说「昨天审了哪些 ID、卡在哪」；每周五产出一份阶段报告（§10.4）。

### 1.2 证据口径（三级，缺一不可）

审核结论必须能落到下面某一级，**不接受「我觉得」**：

| 级别 | 定义 | 典型证据 |
| --- | --- | --- |
| **E1 机械** | 由门禁 / grep / 脚本产出，可复现 | `cargo make check` 输出、`grep -rn` 命中、`twiggy` 报告 |
| **E2 读码** | 逐行读过并二次复核 | `文件:行号` + 因果链（输入 → 错误结果） |
| **E3 复现** | 独立脚本 / 页面操作跑出现象 | 最小复现步骤、截图、测试用例（修复前必红） |

`code-review-2026-10.md` 的教训：E2 漏掉的协议级缺陷（AX.25 FCS）只有 E3 能抓到。
凡是涉及**协议常数、外部格式、跨端互通**的条目，一律要求 E3。

### 1.3 状态与优先级

**状态**：`⬜ 待审` → `🔄 审核中` → `✅ 通过` / `⚠️ 有问题（已记录）` / `⏭️ 不适用（注明原因）`

**优先级**（影响 × 触发概率）：

| 级别 | 判定 | 时限 |
| --- | --- | --- |
| **P0** | 数据错误 / 安全 / 隐私泄露 / 门禁完全失效 | 24 小时内修，修前禁止发版 |
| **P1** | 用户可见的功能错误、明显的口径误导、关键路径无测试 | 本波次内修 |
| **P2** | 规范漂移、重复实现、维护成本、a11y 缺口 | 下一迭代，需有归属 |
| **P3** | 风格、微优化、文档措辞 | 进 backlog，可不修 |

### 1.4 问题记录模板（唯一格式）

每条问题在审核看板（或 Issue）里按以下字段记录：

```
编号：      接 code-review-2026-10.md 的 S/M/A 序列，不另起编号
范围/ID：   A3 / C7 / D-T1-log …（对应本文检查项）
位置：      crates/app/src/pages/xxx.rs:123（必填，指向具体行）
级别：      S / M / A  →  优先级 P0–P3
现象：      一句话说清「什么输入 → 什么错误结果」
证据：      E1 / E2 / E3 + 复现命令或步骤
根因：      机制层面，不写「没注意」
修法：      具体到函数/组件；涉及取舍时写「为什么不选另一种」
回归锚点：  修完后哪条断言会在修复前失败
状态：      ⬜ / 🔄 / ✅ / ❎（不修需写理由）
```

### 1.5 边界（明确不做的事）

- **不重复收录工具链已覆盖的问题**：格式、clippy、未使用变量、i18n 重复 key 等由门禁负责，
  审核只看门禁覆盖不到的地方（这是 `code-review-2026-10.md` 定下的规矩）。
- **审核期不改业务逻辑**：先记录、后集中修，避免边审边改导致基线漂移。只有 P0 允许当场修。
- **不对「刻意的边界」提改进**：ROADMAP 的「刻意不做」与「已知边界」是设计决定，见附录 C；
  审核只核对「代码 / 页面文案是否如实反映了这些边界」。
- **不做性能压测的全量回归**：只对「每帧更新」的页面（频谱、NEC 三维、摩尔斯）做定向测量。

## 3. 范围 A：整体架构

**目标**：确认「分层没有被穿透、常量只有一个出处、错误与边界有统一口径」。
**方法**：读码 + 依赖方向断言 + 同一概念多处实现的 grep 对照。
**产出**：分层违规清单（P1/P2）、单一事实来源缺口表、可疑模块清单（供 E 范围深挖）。

### A1 分层与依赖方向

| ID | 检查项 | 方法 / 证据 | 判定标准 | 产出 |
| --- | --- | --- | --- | --- |
| A1.1 | `ham-web-core` 不依赖浏览器 API | `grep -rn "web_sys\|js_sys\|wasm_bindgen" crates/core/src` + 读 `crates/core/Cargo.toml` | 除 `cfg` 隔离的胶水外零命中 | 违规文件清单 |
| A1.2 | `crates/app` 不承载可单测的纯逻辑 | 抽 20 个 `pages/**` 中含 `fn ` 的文件，看是否有解析/判定/格式化函数 | 纯逻辑在 `core` 且有测试；`app` 只做 DOM 与视图 | 应下沉函数清单 |
| A1.3 | 解码器 crate 不反向依赖 `app` / `server` | `grep -rn "ham-web-app\|ham-web-server" crates/{apt,sstv,wspr,ft8,rtty,olivia,dominoex,navtex,lrpt,hell,wefax,dsp,wav}/Cargo.toml` | 零命中 | 循环依赖图 |
| A1.4 | worker crate 只做胶水 | 读 12 个 `*-worker/src/lib.rs` | 只有导出 / 参数解析 / 错误映射，无算法 | 越界实现清单 |
| A1.5 | `nec` 与 `core` 的 re-export 口径统一 | `grep -rn "pub use" crates/core/src/nec*.rs` + 页面 import | 页面只走 `ham_web_core::{cx, nec, …}` | 双入口清单 |
| A1.6 | 依赖方向无环、无重复 major 版本 | `cargo tree -d`、`cargo tree -p ham-web-app --depth 1` | 无环；重复版本有理由 | 依赖异常表 |
| A1.7 | workspace lint / edition / MSRV 统一 | 读根 `Cargo.toml` | `unsafe_code = "forbid"`、clippy 五组为错误级、MSRV 与 `.tool-versions` 一致 | 偏差项 |

### A2 单一事实来源（SSOT）

沿 ROADMAP 的「建设原则 3」逐条核对：**同一常量是否只存在一处**。

| ID | 概念 | 唯一出处（应然） | 检查方法 | 判定标准 |
| --- | --- | --- | --- | --- |
| A2.1 | 波段边界 | `core/src/bands.rs::AMATEUR_BAND_EDGES` | `grep -rn "1\.8\|3\.5\|144\.0\|430\.0" crates/app/src crates/core/src` 抽查 | 页面不复制频段数字 |
| A2.2 | 操作证权限与功率 | `core/src/license_classes.rs` | `grep -rn "100\s*W\|30\s*MHz" crates/app/src` | 结论由 core 计算，页面只渲染 |
| A2.3 | 路由 / 标题 / 图标 / 分组 | `core/src/registry.rs` | `cargo test -p ham-web-app registry_check` | 注册表 ↔ 导航 ↔ 路由一致 |
| A2.4 | 开放 API 契约 | `core/src/api_v1.rs` | 对照 `crates/server/src/api_v1/` 与 `/developers` 页 | 三者同源，无手抄字段 |
| A2.5 | 配色方案 | `core/src/color_scheme.rs` → `schemes.css` | `cargo make pixel-check` | 生成物与方案表一致 |
| A2.6 | 解码 Worker 协议 | `public/decode-worker.js` + `docs/decode-worker-protocol.md` | 对照 12 个 codec 的路径 / 包名 / `index.html` copy-dir | 四处一致 |
| A2.7 | 内容指纹 | `core/src/fingerprint.rs` | 读注释与 git 历史 | 未改动（动了会导致解析全量失配） |
| A2.8 | 国际 / 地区口径 | 注释与数据一致 | 抽查 `bands.rs` 的「中国三区」注释与 `log_health` / `chirp_csv` | 注释不与数据自相矛盾 |

### A3 领域内核质量

| ID | 检查项 | 方法 | 判定标准 | 产出 |
| --- | --- | --- | --- | --- |
| A3.1 | 公开 API 的错误模型 | 抽查 10 个 `pub fn` 的返回类型 | 用 `Result` / `Option` 表达可预期失败，不用 `panic!` / `unwrap` | 可 panic 点清单 |

## 4. 范围 B：构建与交付

**目标**：确认「同一提交能构建出同一产物、门禁真的会红、交付物真的能跑」。
**方法**：干净 clone 走一遍、故障注入验证门禁、读脚本与 workflow。
**产出**：可复现性结论、门禁有效性结论（逐条给「会红 / 不会红」）、构建耗时与内存记录。

### B1 可复现性

| ID | 检查项 | 方法 | 判定标准 | 产出 |
| --- | --- | --- | --- | --- |
| B1.1 | 工具链钉版本 | 对照 `Dockerfile`、`.github/workflows/*.yml`、`.tool-versions`、`Cargo.toml` 的 MSRV | 三处一致（如 1.99.1），无浮动 `@stable` | 漂移点 |
| B1.2 | wasm-bindgen 版本一致 | `sh scripts/decode-workers.sh` + 三处 awk 解析 `Cargo.lock` | 版本取自锁文件；解析失败有专属报错（不是「版本漂移」） | 误诊风险 |
| B1.3 | 前端构建参数 | 读 `Trunk.toml` / `index.html` / `.cargo/config.toml` | `wasm-opt` 参数、`erase_components`、release profile 与文档一致 | 参数漂移 |
| B1.4 | 干净环境构建 | 新目录 `git clone` → `cargo make setup` → `cargo make ci` | 一次通过，无手工步骤 | 缺失步骤 |
| B1.5 | 构建耗时与内存 | 记录 `cargo make ci` 与 `docker build` 各阶段耗时、峰值内存 | 与 README 实测表同量级；OOM 有明确提示 | 实测表更新 |

### C. 已知边界核对表（页面文案是否如实）

审 D/E 范围时逐条对照，**代码行为不用改，文案不能反着说**：

| 领域 | 已知边界（ROADMAP 口径） |
| --- | --- |
| 考试 | 计算题变体不进模拟考 / 统计 / 错题本 / 收藏 |
| 法规 | 条文原文照录、不译不缩写；未收录的法律不加链接 |
| LoTW | 不调用不打包 TQSL，证书与签名只在本机 |
| 器材 | 不写售价；无可引用来源的规格留空；实测只收原表机型 |
| 日志 | 一键修正只做「频率→波段 / 本地时→UTC / 合并重复」；缺网格不拿实体中心补 |
| SOTA / POTA | 「我的」与「对方」字段严格区分；旧 ADIF 的方向歧义不猜 |
| NEC | 不支持交叉 `TL` 与并联导纳；端点端口导出会移到段心；交叉验证参照是 necpp 而非实测 |
| VNA | 页面不做校准，显示仪器读数 |
| 解码 | WEFAX 未做 1500/2300 Hz FM 副载波；LRPT 的 OQPSK 仅合成验证；FT4 未在真实信号验证；DominoEX FEC 需用户选 |
