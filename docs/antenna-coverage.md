# 天线方向增益 × DXCC 实体（S2 设计说明）

> **已实现**（`core/antenna_coverage.rs` + `pages/nec/direction_table.rs`）。这份文档先立口径、
> 再记录实现与验收，避免做出一页看起来像「覆盖预测」、实际只是天线增益的东西。

## 一句话

在 `/nec` 结果区加一张「方向增益」表：选好本台网格后，列出各个 DXCC 实体方向上的
**天线真实增益（dBi）**与**相对峰值的损失（dB）**。

它回答的是：**这副天线朝那个方向能给出多少增益。**
它**不**回答：那个方向通不通、能通多远、对方能不能收到。

## 为什么必须先把口径写死

站内已经有 `/muf`（简化 VOACAP 的传播可靠度）和 `/dxcc-map`（实体着色）。再放一张
按实体列出 dB 的表，非常容易被读成「这张表告诉我能通哪些国家」。

- 增益高 ≠ 通得上：传播窗口、外部噪声、发射功率、对方天线、极化都没算；
- 增益低 ≠ 通不上：低仰角长跳、灰线、Es 都可能让「背向」的一侧仍然通联；
- 前后比造成的低增益是**方向性**，不是「不通」。

所以页面上的用词必须锁死：标题叫「方向增益」，字段叫 `gain_dbi` / `loss_db`，
**不得出现「覆盖」「可达」「通联概率」**。

## 输入

| 来源 | 用途 |
| --- | --- |
| `NecResult.azimuth: Vec<(φ, gain)>`（360° 全周，1° 步进，仰角固定在最大增益仰角） | 水平面切面；近场比较与前后比自检 |
| `NecResult.elevation: Vec<(仰角, gain)>`（方位固定在最大增益方位） | 单方向仰角剖面 |
| `NecResult.pattern3d`（θ × φ 各 10°，全周；有地面时下半空间填 −300） | 「各仰角最大值」的来源 |
| `station-info.gridsquare`（缺则让用户填） | 本台位置 |
| `dxcc::entities()` 的 `lat` / `lon`（实体中心） | 目标方向与距离 |

## 两种口径

| 口径 | 做法 | 回答什么 | 已知误差 |
| --- | --- | --- | --- |
| **最佳仰角**（默认） | 对方位 φ，在全部 θ 上取 `pattern3d` 的最大值 | 「这个方向最多能给出多少增益」 | 10° 网格会低估窄波束峰值：3 dB 波束约 60° 时误差 ~0.2 dB，约 20° 时可到数 dB |
| **水平面切面** | 在 `azimuth`（1° 步进）上按 φ 线性插值，仰角 = 天线最大增益仰角 | 「水平打一圈」的方向偏好、前后比 | 只代表一个仰角，不代表该方向的最佳仰角 |

默认给「最佳仰角」，并允许切到「水平面切面」做交叉核对。

## 算法

1. 本台网格 → `(lat, lon)`（`grid::lat_lon_from_grid`）。
2. 每个实体：`grid::distance_bearing(home, entity_center)` → 距离 `km` 与方位角 `brg`。
3. 方位 → 方向图 φ：`φ = 90° − brg`（`brg` 先 `rem_euclid(360)`）。方向图的 φ 是 NEC 口径
   （+X 起算、逆时针，见 `crates/nec/src/nec.rs`），地理方位是正北起算、顺时针，两者差
   90° 且旋向相反；这里假设模型里 **+X 指东、+Y 指北**。少了这一步，整张表偏 90° 且
   左右镜像（`/nec` 的极坐标图曾经踩过同款坑，见 `pages/nec/mod.rs` 的 `polar_xy` 注释）。
4. `gain = max_θ pattern3d(θ, φ)`（θ 与 φ 都做线性插值）。
5. `loss = gain_max_dbi - gain`（相对该天线最大增益的损失，理论 ≥ 0，浮点误差钳到 0）。
6. 排序：`loss` 升序；相同 `loss` 按距离升序。
7. 输出：实体名（按界面语言）、方位角（0–359，取整）、距离（km）、`gain_dbi`（1 位小数）、`loss_db`（1 位小数）。

### 网格密度的待定项

`pattern3d` 现在 10° 一格。若实测发现八木的峰值被低估得离谱，有两条路：

- **方案 A**（零成本）：接受 10°，页面注明「窄波束会低估」；
- **方案 B**（推荐）：求解时额外算一份 φ 5° × θ 5° 的网格（点数 ×4，纯前端求解，
  只在打开方向表时按需算一次）。体积不变，成本是求解时间。

**建议先按方案 A 实现并实测**，用一个 3 单元八木对比 `azimuth` 切面的峰值，若误差
超过 0.5 dB 再上方案 B。

## 呈现

- `/nec` 结果区新增折叠块「方向增益（对比 DXCC 实体）」，默认收起（与 DXCC 申请表一样，
  收起时不渲染表格）。
- 顶部固定一句说明：

  > 只算天线本身（含当前地面模型与效率）；未计传播、噪声、功率与对方天线。
  > 增益低不等于通不上，增益高也不等于通得上。

- 表头：实体 / 方位 / 距离 / 增益 / 相对峰值。
- 结果区已有的频率、地面模型、效率随表一起显示——换了地面模型，表必须跟着重算。
- 后续（不在本次）：实体中心落图着色、按波段换频重算对比。

## 验收

单测（`core/antenna_coverage.rs`）：

1. 自由空间半波偶极子：水平面 φ 与 φ+180° 增益相同；端射方向比峰值低 ≥ 6 dB；
2. 八木：反方向的 `loss` 与 `front_to_back_db` 相差 < 0.5 dB；
3. 插值：合成 pattern3d，任意角度的取值落在网格最小 / 最大值之间；
4. 一致性：同一 (θ_best, φ) 上，方向表与 `azimuth` 切面的差 < 0.01 dB；
5. 口径：`pattern_phi` 的四个象限（东→0°、北→90°、西→180°、南→270°），以及「只有正东
   有峰值的切面，峰值必须落在指向最接近正东的实体上」；
6. 实体中心缺失 / 网格非法：返回空表或错误，不 panic。

e2e：

- 默认预设 → 填网格 → 展开方向表 → 至少 1 行；
- 切到「自由空间」后数值发生变化；
- 页面上能找到「未计传播」的说明文案。

## 不做什么

- 不做「覆盖地图」「可达性评分」「通联概率」；
- 不做 SNR 预测，不接噪声模型（那是 ROADMAP 里 P.372 的独立条目）；
- 不在 `/nec` 设计存档里保存方向表（避免存档带一份过期的派生数据）。

## 边界与风险

- **实体中心是近似**：美国、俄罗斯、中国、加拿大这类跨度大的实体，中心与实际目标
  相差可达 10° 以上。统一在说明里写清，不针对个别实体做特殊处理。
- **地面模型影响很大**：同一副天线在「理想地 / 有耗地 / 自由空间」下低仰角增益差十几 dB，
  表必须显示当前地面模型，且不能跨模型比较。
- **不要拿它当购买决策的唯一依据**：它能回答「朝向对不对」，回答不了「这副天线在你家
  能不能通 EU」。
