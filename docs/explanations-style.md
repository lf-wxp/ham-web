# 题目解析写作规范

> 面向 `data/explanations.json` 的**解析正文**。维护流程（缺失统计 / 合并 / 术语增强 / 回写题库）见 [README § 题目解析维护流程](../README.md#题目解析维护流程)，本文只规定「一条解析该怎么写」。

## 1. 定位与读者

解析会出现在五个场景，写法必须同时满足它们：

| 场景 | 约束 |
| --- | --- |
| 练习 | 折叠卡片，默认收起，需要一眼扫到结论 |
| 模拟考试 | **交卷后**才可见，此时读者已知对错，需要「为什么」 |
| 错题本 | 与笔记编辑器相邻，需要可摘抄的易错点 |
| 打印卷 | 纸质、无交互、字号小 → 篇幅要短、不能有链接/富文本 |
| 朗读（`speech::speak_zh`） | 纯文本朗读 → 不能有 Markdown、HTML、半角符号乱读 |

**读者画像**：零基础备考者，第一次见到这个知识点。解析的目标是让他下次遇到同类题能做对，而不是证明答案正确。

> **详细优先**：读者是新手，解析要「讲透」而不是「点到」。宁可长一点让人看懂，也不要为了短而省掉依据和排除过程。篇幅的唯一上限是「不啰嗦重复」，不是「越短越好」。

## 2. 唯一数据源原则

- 权威副本只有 `data/explanations.json`（key = 内容指纹）。
- `public/questions/*.json` 里的 `explanation` 是**构建产物**，由 `cargo make explanations-apply` 写入，**禁止手改**（下次构建必被覆盖）。
- 术语解释**不在解析里手写**，交给 `explanations-enhance` 注入；手写会导致与术语表口径漂移、重复运行时重复出现。
  例外：工具会把「超视距、副载波、线性调频、必要带宽、接收带宽、恒定包络、亚音调静噪」等**更长词语**整体跳过（见
  `crates/tools/src/explanations.rs` 的 `BLOCKED_COMPOUNDS`），此时可以在句内用短语限定词义，例如
  「MF 中频（中波，300kHz–3MHz）」，但不要照抄术语表的释义原文。

## 3. 结构模板（五段，常规全写）

```text
① 定性 + 结论 → ② 依据 → ③ 排除干扰项 → ④ 易错点 → ⑤ 延伸（可选）
```

1. **定性 + 结论**：先说题型和答案，多选题点明「需同时选出 X、Y」。
2. **依据**：法规题写文件名与条款；技术题给公式、量纲或原理；操作题给规程来源。**新手不知道的背景（这个概念是干什么的、用在哪）要在这里补一句**。
3. **排除干扰项**：每个错误选项一句，说明它**为什么像是对的**（旧称 / 俗称 / 主体错位 / 范围错）。**单选也要写，至少覆盖两个最像的干扰项**。
4. **易错点**：一句话，指向最典型的混淆（如「办法 vs 条例」「制定机构 vs 执行机构」）；数值题给「数量级记忆法」。
5. **延伸**：可选，只在有助于记忆时写。

只有 ① 的解析视为不合格（红线第 2 条）。定义 / 数值题同样要写 ②③，见 §4。

示例（符合规范）：

> 本题是「文件 + 制定机构」双问组合题，两个正确点需同时选出。我国专门针对无线电管理的行政法规是《中华人民共和国无线电管理条例》，由国务院和中央军事委员会联合制定，故 A（法规名称）、C（制定机构）正确。B《无线电管理办法》名称不规范、非正式法规名；D 工业和信息化部是条例的执行与监督机构，而非制定机构。

反例（禁止）：

- ❌ 「答案是 A、C。」——只复述答案，等于没写。
- ❌ 「根据相关规定，A 是正确的，其他选项不正确。」——依据缺失、排除缺失。
- ❌ 「《无线电管理条例》由工业和信息化部制定……」——与标准答案矛盾，比没有解析更糟。

## 4. 先判断题型：定义题 vs 判据题

同样是「一句话解析」，合理性差别很大，先判断题型再决定写多少：

| 题型 | 特征 | 解析要求 | 示例 |
| --- | --- | --- | --- |
| **定义 / 名词 / 数值题** | 答案本身就是知识点（单位、缩语含义、术语定义、法条罚款数额） | 结论 + **一句背景 / 用途 / 记忆锚点** + 排除最像的那个干扰项；不写「为什么是这样」，但要写「它是什么、和别的有啥不一样」 | 「电压的单位是伏（A）。电流用安、电阻用欧、功率用瓦，别混；伏特（V）是电势差的单位，不是电量。」 |
| **判据题** | 选项是并列的多个具体场景 / 做法，需要判据才能选对 | 必须写清「为什么」，并**逐项排除**干扰项 | 「应选择较短的 AGC 时间常数的情况是…」 |
| **对比题** | 一对镜像题（较长 / 较短、上行 / 下行、NFM / WFM） | 两条要互补：正面给判据，反面点明差异，避免写成同义反复 | AGC 长/短常数、上下边带 |

判据题最易退化成「题干 + 正确选项 + （A）」的复述——这是红线第 2 条，写作后请对照检查。

## 5. 分类写法要点

| 题型 | 必写内容 |
| --- | --- |
| 单选 | 结论 + 依据 + 三个干扰项各一句 |
| 多选 / 组合题（如「文件及其制定机构分别是」） | 明确几个正确点、分别对应哪个选项；说明漏选即错 |
| 法规题 | 文件名要**全称**、尽量给条款号；区分「制定 / 执行 / 监督」主体；标注已废止旧称 |
| 计算 / 技术题 | 给公式与代入过程（一句话），说明单位与量级；给出「数量级记忆法」 |
| 简语 / 缩语题（Q 简语、缩语） | 给全称 + 使用场景，避免只给中文翻译 |
| 图形题（带 `imageUrl`） | 先描述图中关键特征，再给结论，避免读者看不到图时完全无法理解 |

## 6. 语言与格式硬约束

1. **纯文本**：不写 Markdown（`#`、`**`、`[x](y)`）、不写 HTML、不用列表符号。换行仅用于分段，渲染为 `whitespace-pre-line`。
2. **长度**：常规 3–6 句、约 **80–200 字**（目标中位数 ≈ 130 字）。< 60 字基本撑不起「依据 + 排除」，需要扩写（图形符号、缩语类题目可短些）；> 300 字应拆分，或考虑是否该进知识库 / 术语表而非解析。
3. **括号**：术语解释由工具注入为 `（…）`，因此正文**不要**给术语自带解释；已有括号内容保持配对，避免嵌套 `（（…））`。
4. **选项引用**：统一用 `A`、`B`、`C`、`D` 半角字母，与答案键一致；多选题写「A、C」而非「AC」。
5. **确定性**：不用「大概 / 可能 / 应该是」；不确定时宁可不写该项，也不要给含糊结论。
6. **一致性**：同一知识点在不同题中的表述（法规全称、机构名称、术语叫法）必须一致，以术语表 `data/glossary/` 为准。
7. **空白**：首尾不留空白，正文内部不出现连续空格 / 制表符（写入时会 `js_trim`，但源数据也应干净）。
8. **中文标点**：用全角「，。：；」，英文缩写（SWR、PEP）保持半角原样。

## 7. 质量红线

出现以下任一情况，该条视为不合格，需要重写：

- 与题库 `answer_keys` 矛盾（把错误项写成正确项）。
- 信息量不足：长度 < 40 字（缩语、图形符号题除外），或只是复述「正确选项是 X」。
- 只有结论、没有依据或排除过程。
- 出现「本题无解析 / 略 / TODO / 待补充」等占位内容。
- 大段照抄题干或选项原文。
- 注入后产生嵌套括号 `（（…））`。
- 同一术语的括号解释在该条中出现 2 次及以上（注入只应命中首次出现；重复是历史遗留或括号结构异常，需人工去重）。
- 术语释义被注进更长词语内部（如「超视距（收发两点之间看得见的直线传播）」「副载波（被声音等信息骑在上面的那个高频电波）」），或释义被手抄进正文而没加括号。
- 超过 400 字（应移到知识库 / 术语表）。

## 8. 审查清单（提交前）

```bash
cargo make glossary-check          # 术语表合法性与 inject 条数
cargo make explanations-missing    # 覆盖缺口，应输出「缺失 0」
cargo make explanations BATCH=tmp/batch.json
cargo make explanations-check      # 解析表硬校验：答案一致性 / 错位注入 / 重复注入 / 嵌套括号 / 裸释义 / 多指纹分叉
cargo make explanations-sync       # 对齐同一道题多指纹变体的解析文本（已并入 `cargo make explanations`）
```

`explanations-check` 会把上述硬错误以非零状态退出（已挂进 `cargo make check` 与 `cargo make ci`）。
当前基线（应长期保持）：

```text
答案键与解析声明矛盾：0
错位注入（释义注进更长词语内部）：0
重复注入（同一条里相同括注出现多次）：0
嵌套括号（（…））：0
裸术语释义（未加括号）：0
同一道题多指纹但解析文本不一致：0（题库已统一排版，多指纹变体组应为 0）
```

人工抽查：

- [ ] 随机抽 10 条，确认结论与 `answer_keys` 一致；
- [ ] 检查同题分叉：同一道题在不同题库里的解析文本应一致（`cargo make explanations-check` 报 0；
      若不为 0，先按 [`docs/typography.md`](typography.md) 统一题面排版，再跑 `explanations-sync`）；
- [ ] 检查详细度（过短条目应扩写，基线：`< 60 字` 条数持续下降，目标中位数 ≈ 130 字）：
      ```bash
      python3 -c "
      import json,collections
      e=json.load(open('data/explanations.json')); L=sorted(len(v) for v in e.values())
      c=collections.Counter('<60' if x<60 else '60-99' if x<100 else '100-149' if x<150 else '>=150' for x in L)
      print(len(L),'中位',L[len(L)//2],dict(c))"
      ```
- [ ] 检查是否有「照抄题干」的条目（去掉括注后与题干高度相似、且没有任何说理或排除表述）：
      ```bash
      python3 -c "
      import json,re,difflib
      e=json.load(open('data/explanations.json'))
      clean=lambda s: re.sub(r'[，。、：；？！「」“”‘’\s]+','',re.sub(r'（[^（）]*）','',s))
      R=re.compile('因为|由于|因此|所以|故 |错在|不是|而非|用于|以便|以免|否则|原因|区别|注意|意味着|导致|其余|不匹配|不相符|旧制度|超出|不适用|不属于|不可取|不能')
      bad=[k for k,v in e.items() if len(clean(k.split('||')[0]))>=25
           and difflib.SequenceMatcher(None,clean(k.split('||')[0]),clean(v)).ratio()>=0.55 and not R.search(v)]
      print(len(bad))"
      ```
      当前基线为 **0 条**；
- [ ] 多选题是否写明了「需同时选出」；
- [ ] 打印预览（`/print`）下解析不跨页断裂、篇幅可接受；
- [ ] 朗读一遍最拗口的条目，确认无符号导致断句异常。

### 已修复的缺陷（回归防线）

- **术语注入跨运行不收敛**：`inject` 单次运行只注入每个术语的首次出现，反复 `enhance` 会在同一条解析里堆出多处相同括注（曾累积 36 条）。现在命中规则增加「该术语的注入结果已存在则跳过」，跳过时仍占位，避免更短术语（如「边带」）插进「单边带」内部。
- **`full.json` 是巡检盲区**：`missing-explanations` 原先只遍历 A/B/C，full 题库的 48 题缺失解析一直发现不了。现在 A/B/C/full 全部纳入巡检与合并（`--bank` 仍只能选 A/B/C）。
- **释义注进更长词语内部**：早期注入只按子串匹配术语，写出了「超视距（收发两点之间看得见的直线传播）」「副载波（被声音等信息骑在上面的那个高频电波）」「亚音（…）调静噪（…）」等错误或读不通的句子（曾清理 95 处）。现在 `inject` 增加复合词阻止表，`dedupe-explanations` 会把已存在的错位括注删掉（先摘掉括注还原文本，再判断术语是否落在更长词内部）。
- **解析表硬校验**：新增 `cargo make explanations-check`，检查答案键与解析声明是否矛盾（「误选 D」这类提醒不算声明）、错位注入、重复注入、嵌套括号、裸术语释义，以及「同一道题多指纹但解析文本不一致」。前几类曾在本轮审查中各发现数十处。
- **同题多指纹分叉**：题库 JSON 由 CSV 生成，同一道题在不同题库里可能因空格写法不同（「25 瓦」与「25瓦」）得到不同指纹，解析表里就留下多份内容不同、甚至互相矛盾的解析（曾出现 663 组）。现在：
  - `cargo make explanations-sync` 按内容 key（忽略空白）分组，保留最详细的一条并写回该组全部指纹，明细写入 `tmp/explanations-sync-report.json`；该步骤已并入 `cargo make explanations`；
  - `explanations-missing` 的模板也按内容 key 去重，作者不必为空格变体重复填写；
  - 练习模式的「只看本类新增」改用内容 key 判重，同一道题不会再被当成「本类新增」出一遍。

## 9. 提交约定

- 只提交 `data/` 与 `public/questions/`（`tmp/` 为临时目录，不入库）。
- 提交信息：`docs(explanations): 补充 C 类解析 50 条`。
- 修改已有解析时，同样把题目 ID 写进 batch 覆盖，避免直接编辑 900 KB 的解析表引发大 diff。
