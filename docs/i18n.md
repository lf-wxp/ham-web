# 界面多语言（i18n）规范

> 写给**要改界面文案的人与 AI agent**。这个仓库的界面文案只有一套来源：
> `data/i18n/{zh,en,es}/<域>.json`；源码里只写语义 key（`t("shell.home")`），
> 中文与英 / 西一样只是其中一份译文 —— 改中文文案不会再让其它语言的译文静默失效。
>
> 本文件管**怎么写、怎么改、怎么验**；控件与页面结构另见 [`ui-components.md`](ui-components.md)；
> 知识库正文译文是另一套机制，见 §11。
>
> 从哪读起：新写 / 改文案看 §1 → §3 → §5；带数量的文案看 §4；收工前过 §12；
> `cargo make check` 红了查 §8；「这里为什么这么设计」查 §9。

## 1. 三条底线

1. **源码里不写界面中文**：文案一律 `t("域.词条")` / `tf` / `tp`，字面量写在调用点（不先抽
   `const`），`tf` / `tp` 的实参里也不写中文 —— 实参没有反向索引，会原样漏到 en / es 界面。
2. **词条只改 `data/i18n/{lang}/{域}.json`**：zh / en / es 三份齐全，改完跑
   `cargo make i18n-pack` 刷新运行时语言包（产物 `public/data/i18n/` 不入库）。
3. **提交前 `cargo make check` 必须全绿**（已含 `i18n-pack` + `i18n-check`）；动了页面组件
   再跑相关 e2e —— 复数与三语布局回归见 §7。

## 2. 架构：词条从 JSON 到界面

```
作者层（人写）                    机器层（校验/索引）              运行层（查表）
──────────────────────────────────────────────────────────────────────────────────
data/i18n/{lang}/{domain}.json  ──►  check-i18n  ──►  build.rs 代码生成  ──►  t() / tf() / tp()
  ├ zh/{shell,exam,…}.json           重复 key            i18n/catalog.rs        （同步、响应式，
  ├ en/{shell,exam,…}.json           占位符一致          内嵌域静态表            API 稳定）
  └ es/{shell,exam,…}.json           死条目                  ↓ 未命中
                                     按域覆盖率         i18n/pack.rs
                                     语言包新鲜度        运行时语言包（按语言 fetch）
                                          │
                                          └──► i18n-pack ──► public/data/i18n/{lang}.json
```

三层职责分开：**作者只关心自己那个域的 JSON**，机器保证全局一致，运行时只看到一张表。

| 文件 | 职责 |
| --- | --- |
| `data/i18n/{lang}/{domain}.json` | **唯一事实源**：词条本体（手写、入库） |
| `crates/app/build.rs` | 构建期把 JSON 编成 `OUT_DIR/i18n_catalog.rs` 静态表（不入库） |
| `crates/app/src/i18n/mod.rs` | 运行时 API：`Locale` / `locale()` / `set_locale()` / `t` / `tf` / `tp` / `bank_class`，不含词条 |
| `crates/app/src/i18n/catalog.rs` | 内嵌域查表索引、中文反向索引、复数表 |
| `crates/app/src/i18n/pack.rs` | 运行时语言包：非内嵌域译文，按语言拉一次 |
| `crates/tools/src/i18n.rs` | `check-i18n` / `add-i18n` / `i18n-pack` 的实现 |
| `crates/core/src/plural.rs` | CLDR 复数类别规则（纯逻辑 + 单测，不依赖浏览器） |
| `public/data/i18n/{lang}.json` | `i18n-pack` 产物（不入库；Trunk 在 dev / release 都会拷进产物目录） |

合计 zh 3669 条，en / es 与之**逐 key 一致**（其中 110 条是复数词条）。

只有中文全量内嵌（默认语言不该为「界面本来就是中文」付一次网络请求）；en / es 只内嵌
`common` / `shell`（首屏与离线兜底的最小集合），其余域由运行时语言包提供。

**查表链**（`t()` 是同步的，`tp()` 只多一级复数表，调用点因此不必等待、也不会闪）：

```
t(key):  内嵌扁平表 → 内嵌复数表的 other → 运行时语言包（flat → plural.other）→ 中文 → 原样返回 key
tp(key, count, args):  内嵌复数表[类别] → 语言包复数表[类别] → 上面整条链（缺类别回退 other）
```

- 语言包在**挂载之前**（`main.rs`）与**切语言之前**（`set_locale`）载入，界面不会「先中文后译文」；
- 拉包超时 3 秒，失败后按 3 秒 × 最多 3 次重试；包到达会 bump 版本信号，已渲染的视图自动重算；
- 切语言带请求序号：慢包回来时若用户已改选别的语言，这次结果会被丢弃（否则界面与 `localStorage` 里记的不一致）；
- 中文反向索引：`t()` 的入参若是中文原文，会查「中文原文 → key」映射。这是给 `crates/core`
  registry（导航分组名、页面标题等**运行时**传入的文案）兜底的，**业务代码请写语义 key**。

## 3. 词条规范

**key 形态**：`<域>.<slug>`，slug 由英文译文派生（`shell.repeater-building`），全小写、连字符分词。

```jsonc
// data/i18n/zh/common.json —— 中文永远写成字符串，写了复数对象构建期直接报错
"common.days": "{} 天"

// data/i18n/en/common.json —— 需要按数量换词形时才是对象，other 必填
"common.days": { "one": "{} day", "other": "{} days" }
```

**硬规则**（违反会被 `cargo make check` 拦下，见 §8）：

1. **域前缀必须与所在文件一致**：`log.xxx` 只能住在 `data/i18n/{lang}/log.json`。
2. **同一语言内 key 唯一**：跨域重复同样算（后写的会静默覆盖先写的；`build.rs` 也会 fail-fast）。
3. **不要新增编号 slug**（`common.correct-2` 这种「slug 冲突自动加序号」的产物）：语义为零，
   存量已冻结在 `NUMBERED_SLUG_BASELINE` 清单里待重命名，新增一条就红。撞名时换一个语义化 slug。
4. **中文释义必须唯一**：`zh_reverse()` 是「中文原文 → key」的**单值**映射，两条 key 共用同一句
   中文时后写的覆盖先写的，另一条靠反向索引的调用点会静默拿到别的译文 —— 要复用同一句中文，
   就复用同一个 key。
5. **占位符 `{}` 数量以中文侧为准**（复数词条的每个变体单独比对）：少了会丢实参，多了会漏出 `{}`。
6. **词条值只能是字符串或复数对象**，其余 JSON 类型在构建期报错。
7. **不要写 `\u{…}` 字面量**：JSON 里写成 `"\\u{2026}"` 时解码出来是反斜杠加 `u{2026}` 这串文本，
   界面会原样显示。直接写 `…`、`“”`、`«»` 这些字符。
8. **保持文件内 key 顺序**：`add-i18n` 保序、且只写内容真的变了的域文件；不要为了整齐整体重排
   （回填 diff 里会全是键重排噪声）。

## 4. 复数规范（数量 + 可数名词）

英文 / 西语下 `1 day` / `2 days` 要换词形，而 `tf` 一个 key 只有一条译文，因此带数量的文案要走 `tp`：

```rust
// data/i18n/en/log.json: "log.grid-qsos": { "one": "Grid {} · {} QSO", "other": "Grid {} · {} QSOs" }
tp("log.grid-qsos", qsos, &[&grid, &qsos.to_string()])
```

- **变体名限定 CLDR 六类**（`zero` / `one` / `two` / `few` / `many` / `other`），**`other` 必填**；
- **`count` 单独传、不占 `args`**：决定词形的量未必是第一个占位符
  （`common.questions-left-unseen-in` = `{} 类还有 {} 题没做过`，决定词形的是第 2 个占位符）；
- **中文不写复数对象**：`tp` 在中文下直接退化为 `tf`，零额外开销；
- **没有复数变体的词条，`tp` 与 `tf` 完全等价** —— 迁移可以一条一条做，未迁移的调用点零行为变化；
- 复数词条被老调用点 `t(key)` 查到时返回 `other` 变体，不会漏出 key 或中文。

**什么时候不用 `tp`**（`--plural-candidates` 导出的候选要人工过一遍）：

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 英文不变形 | 百分比 `{}%`、单位 `{} min` / `{} km`、序号 `Question {} / {}`、纯数值 `{}` | 保持 `tf` |
| `{}` 不是数量 | `learning.show-only-mistakes` 的 `{}` 是专题名；`log.time-notes` 的 `{}` 是备注文本 | 保持 `tf` |
| 浮点 / 恒 > 1 | `tools.runtime-hours`（`{:.2}`）、`CHALLENGE_COUNT` 这类编译期常量 | 保持 `tf` |

**一句话只放一个「数量 + 可数名词」**（写作规范 L1，`check-i18n` 硬门禁）：`tp` 只吃一个 `count`，
一句里塞两个可数名词就管不了。拆不动时按优先级处理：

| 层级 | 做法 | 适用 |
| --- | --- | --- |
| L1 写作规范 | 并列句拆开写，一句一个「数量 + 名词」 | 所有新增文案（源头治理） |
| L2 嵌套格式化 | 外层模板只留 `{}` 承接，内层片段各自 `tp` | 语序一致、可拆的并列句 |
| L3 改写 | 只留一个可数名词，其余改成无量词表达（`best: 7`） | 拆不动的短句 |

```rust
// L2：外层 "log.imported-records-skipped-duplicates" = "{}，{}"
tf("log.imported-records-skipped-duplicates", &[
  &tp("log.imported-records", added, &[&added.to_string()]),
  &tp("log.skipped-duplicates", dupes, &[&dupes.to_string()]),
])
```

**多个数量共用一个名词**（B 类）不是障碍：把 `count` 传给决定词形的那个数（通常是总数 / 后一个数）即可。

**复数类别规则**集中在 `crates/core/src/plural.rs`（配单测）：

| lang | 类别 | 规则 |
| --- | --- | --- |
| `en` | `One` / `Other` | `One`：整数部分为 1 且无小数位 |
| `es` | `One` / `Other` | 同上（`1 / 1 correcto` 这类靠 `count` 传对数） |
| `zh` | `Other` | 恒定（`tp` 在中文下根本不查复数表） |

`zero` / `two` / `few` / `many` 在**存储与查表通路里已预留**（词条可写、能命中），只是当前三种语言的
规则函数不产出 —— 将来加俄语 / 阿拉伯语，只改这张表 + 加一个 `data/i18n/<lang>/` 目录。

**迁移不是全自动的**：`{}` 里哪个是 count、单复数怎么变形，机器判断不了；
`cargo make i18n-plural-candidates` 只导出骨架与调用点行号，人工确认后再把 `tf(` 改成 `tp(`。

## 5. 调用点规范

| 场景 | 用 |
| --- | --- |
| 静态文案 | `t("域.词条")` |
| 带占位符 | `tf("域.词条", &[…])` |
| 带数量、译文会变词形 | `tp("域.词条", count, &[…])`（见 §4） |
| 页面标题 | `set_title("域.词条")`；带实参用 `set_title_with_args("域.词条", &[…])`（实参也会过一次词典） |
| 题库类别标签 | `bank_class(bank)`（词序按语言：`B 类` / `Class B` / `Clase B`） |

- **字面量写在调用点**：不要 `const TITLE_KEY: &str = "shell.home"` 再传变量 —— 静态扫描认不出来，
  该 key 会被判成死条目。**数据驱动的例外**（`headers = &["knowledge.model", …]` 把 key 当数据传）
  是允许的（`unused()` 认「key 字面量出现在源码里」），但条目改名时要顺手删掉旧的 key，别指望扫描器报出来。
- **不要在 `tf` / `tp` 的实参里写中文**：实参只按 `{}` 顺序填进去，没有反向索引，en / es 界面会原样
  漏出中文（`check-i18n` 会红）。文案拆不动的场景走 §4 的 L2。
- **不要用 `format!` 拼中文句子**：整句在 en / es 下仍是中文，而且标点是硬编码的
  （连标点都要按 `locale()` 切换）。
- **属性文案要响应式**：`aria_label` / `placeholder` / `title` 用 `Signal::derive(|| t("…"))`，
  一次性求值会在切语言后停在旧语言（这些属性同时是 e2e 的定位契约）。
- **动态 key 尽量避免**（`t(&format!("…"))`）：静态扫描认不出，`check-i18n` 会提示「首个实参不是
  字面量」，对应的 key 可能被误判成死条目或漏出覆盖率。
- **不依赖浏览器的逻辑放 `ham-web-core` 并带单测**（复数类别、语言相关判定），`crates/app` 只做
  DOM 与视图。

## 6. 工作流：新增 / 修改 / 删除

**新增一句文案**（照常写 `t("域.词条")`，再补译文）：

```bash
cargo make i18n-check            # 报「待补：域.词条」；写错的 key 在这里现形
cargo run -q -p ham-web-tools -- check-i18n --missing tmp/ui-missing.json --lang en
# 填 tmp/ui-missing.json 里的 text 字段（key 与 zh 已填好，zh 仅作参考）
cargo run -q -p ham-web-tools -- add-i18n tmp/ui-missing.json --lang en
# es：把上面两条的 --lang 换成 es 再来一遍
```

`add-i18n` 按 key 的域前缀定位到 `data/i18n/{lang}/{domain}.json`，回填完自动刷新运行时语言包。

**改一句已有文案**：直接改 `data/i18n/{lang}/{域}.json`，再跑 `cargo make i18n-pack`。
（语义 key 保证改中文不会让别的语言失效；`i18n-check` 会校验语言包与 `data/i18n/` 是否一致。）

**删一句文案**：删掉源码里的调用点与该 key 的三语言条目；`i18n-check` 会把「词典里有、没人用」
的条目列为死条目，兜住漏删。

**新增一个页面**：key 前缀用页面所属域，通常只触碰 1~2 个 JSON。

**新增一个域**：三个语言目录下各建一个同名 JSON 即可（`build.rs` 与工具按目录发现，无需登记）；
除非首屏必需，不要加进 `BUNDLED_DOMAINS`（那会让每种语言都多背一份内嵌体积）。

**新增一种语言**：`data/i18n/<lang>/`（15 个域文件，key 集合与 zh 一致）+ 代码三处
（`crates/app/build.rs` 的 `LANGS`、`crates/tools/src/i18n.rs` 的 `LANGS` / `check_lang`、
`Locale` 枚举与 `ALL` / `code` / `label` / `intl_code` / `from_code`）+ 复数规则
（`crates/core/src/plural.rs`）；e2e 的三语布局 / 复数回归按需扩语言。

## 7. 命令清单

| 命令 | 做什么 |
| --- | --- |
| `cargo make i18n-check` | 校验词典（重复 key / 命名空间 / 占位符 / 复数 / 多计数 / 实参中文 / 死条目 / 覆盖率 / 语言包新鲜度） |
| `cargo make i18n-pack` | 生成 `public/data/i18n/{lang}.json`；**改了 `data/i18n/` 就要跑** |
| `cargo make i18n-plural-candidates` | 导出复数候选骨架 → `tmp/plural-candidates-en.json`（`-- --lang es` 换语言） |
| `… check-i18n --missing <path> --lang en\|es` | 导出「源码用了、词典没有」的待译模板 |
| `… check-i18n --plural-candidates <path> --lang en\|es` | 导出复数候选（含调用点行号，供人工确认 count 对应哪个占位符） |
| `… add-i18n <path> --lang en\|es` | 把填好的模板合并回域文件，并刷新语言包 |
| `cargo make check` / `cargo make ci` | 全量门禁：`i18n-pack` + `i18n-check` 已并入（`check` = fmt + clippy + test + i18n-pack + i18n-check + knowledge-i18n-check + explanations-check + pixel-check） |

e2e（`cd e2e && E2E_BASE_URL=… npx playwright test tests/<spec>`）：

| spec | 守什么 |
| --- | --- |
| `i18n_plural.spec.ts` | en / es × 会渲染计数型文案的路由（`ROUTES`），种 count = 1 数据后扫可见文案与 `title` / `aria-label`，断言不出现 `1 <复数名词>`，并反向断言至少命中一次单数形式 |
| `i18n_layout.spec.ts` | 全部路由 × 三语布局回归（横向溢出 / 文本裁剪 / 越界） |
| `knowledge_i18n.spec.ts` | 知识库正文译文（见 §11） |

**新增计数文案时**：把渲染它的路由加进 `i18n_plural.spec.ts` 的 `ROUTES`，名词表补上对应名词
（守门词表会自动从已迁的复数变体派生，e2e 里另有一份兜底名单）。

## 8. 校验与门禁

`cargo make check` 里**判失败**（红）的项：

| 检查 | 触发原因 | 怎么修 |
| --- | --- | --- |
| 漏 key | 源码 `t("shell.hme")`，词典里没有 | 补三语言词条（§6） |
| 死条目 | 词典有、源码里 key 与中文原文都搜不到 | 删词条；数据驱动的 key 已算「在用」 |
| 三方 key 集合不一致 | zh / en / es 有一方缺 key | 补齐（否则运行时会回退中文或漏出 key） |
| 重复 key | 同一语言内（含跨域）两条同名 | 删掉一条，检查覆盖关系 |
| 命名空间不一致 | key 前缀 ≠ 文件名 | 挪到正确的域文件 |
| 占位符数量不一致 | 与中文侧 `{}` 数不同（复数变体逐个比） | 对齐 `{}` |
| 复数变体非法 | 变体名不在 CLDR 六类 / 缺 `other` / 中文用了对象 | 按 §4 写 |
| 一句话多个可数名词 | 文案里 ≥ 2 处「`{}` + 可数名词」 | 按 L1 / L2 / L3 改写（§4） |
| `tf` / `tp` 实参含中文 | 实参里裸写中文 | 抽成词条，或套一层 `t()` |
| 中文释义重复 | 两条 key 共用同一句中文 | 合并为同一个 key |
| 新增编号 slug | 新出现 `xxx-2` 且 `xxx` 存在 | 换语义化 slug |
| 语言包过期 | 改了 `data/i18n/` 没跑 `i18n-pack` | `cargo make i18n-pack` |

另有构建期 / 单测层的守门：

- `build.rs` fail-fast：跨域重复 key、zh 使用复数对象、变体缺 `other`、词条值类型不对；
- `catalog.rs` 单测（`cargo test` 与 `trunk build` 都会跑）：内嵌域在每种语言里齐全、
  en / es ⊆ zh、占位符一致、中文释义唯一、key 带域前缀、复数变体合法；
- `crates/core/src/plural.rs` 单测：0 / 1 / 2 / 21 / 1.5 / 负数 / 极值 / 未知语言。

**只提示、不判失败**：`tp()` 调用但词典没配变体 / 词典配了变体但源码没有 `tp()` 调用（迁移是增量的）、
复数候选条数、首个实参不是字面量的调用点（工具无法自动解析，需人工核对）、基线清单里已不存在的编号 slug。

## 9. 关键取舍

| 决策 | 为什么 |
| --- | --- |
| 语义 key + JSON 单一事实源 | 中文原文作 key 时改一个中文字符 = 译文静默失效并留下死条目；JSON 里作者不用管 Rust 转义与 rustfmt 对齐 |
| 构建期代码生成静态表（而非运行时拉全量词典） | `t()` 保持同步、零网络、零闪烁；词典只占 wasm 的百分之几，改 JSON 也不必碰源码 |
| en / es 只内嵌 `common` / `shell`，其余走运行时语言包 | 中文用户不为 en / es 付流量；包在挂载前 / 切语言前载入，仍然零闪烁（wasm 少了一百多 KB，代价是非中文首次多一次约 50 KB 的请求） |
| 不上 ICU MessageFormat / Fluent | 要引入运行时解析器（约 +100 KB wasm）并把全部词条改写成新语法，破坏「`t()` 同步查表」这条核心保证；本项目只有三语、只用 `one` / `other`，自建内核更可控 |
| `tp` 只吃一个 `count`（不做组合变体） | 类别组合按 2ⁿ 爆炸（3 个名词 = 8 组变体），存储 / 翻译 / 校验三方成本失控；真正需要多计数的文案只有个位数 |
| 语言包不进 SW 预缓存清单 | 内容哈希仍并入 `__CACHE_VERSION__`（改译文照样换缓存版本），但改走运行时按需缓存，中文用户不为 en / es 的包买单 |
| 切语言带请求序号 | 包是异步到达的：点 es（开始拉包）→ 再点 en → es 包回来时不能把界面改回西语（会导致与 `localStorage` 不一致） |
| 保留中文反向索引 | `crates/core` registry 的导航分组名 / 页面标题是运行时传入的，拿不到编译期 key；业务代码不依赖它 |

## 10. 常见坑

- **改了 `data/i18n/` 却忘跑 `i18n-pack`**：dev 与 release 拷到的都是旧包，en / es 界面是旧译文且
  没有任何报错。`i18n-check` 会比对产物与源目录的字节内容；`add-i18n`、`build-web`、Docker 构建
  都会自动刷新。
- **dev 产物缺 `public/` 资产**：`curl -s http://127.0.0.1:3030/data/i18n/en.json | head -c 1` 返回 `<`
  就说明语言包被 SPA 回退成了 `index.html`（症状：英文 / 西语界面回退中文，甚至整页空白），
  重跑一次 `trunk serve`（或 `cargo make dev`）即可。
- **中文释义重复**：症状是「某条文案在换语言后显示的却是另一句的译文」，且没有任何报错 —— 靠检查兜住。
- **实参多于占位符**：多出的实参被静默丢掉（页面上只表现为「少半句话」），开发期另有一条
  `console.warn`；实参自带 `{}`（呼号、备注、搜索词）不会错位 —— `substitute` 从上次替换结束处继续找。
- **文案改名后旧 key 残留**：死条目会红；但「把 key 当数据传」（`headers = &[…]`）的口径偏宽，
  等于 key 的字面量都会把它「救活」，改名后要自己删掉旧 key。
- **单测里构造的调用**不会干扰扫描：扫源码前会把 `#[cfg(test)] mod …` 整块涂白（保留行号），
  单测里的 `tp("shell.home", 1, &[])` 不会制造死条目 / 复数对账的假阳性。
- **慢网首屏**：语言包 3 秒超时后先放人进来（非内嵌域回退中文），随后 3 秒 ×3 次重试；包一到，
  已渲染视图自动重算。看到「混排语言」先确认网络与 `dist/data/i18n/*.json` 是否到位，别急着改代码。

## 11. 知识库正文译文（另一套机制）

知识页正文的译文**不走**上面的词典：它在 `data/knowledge-i18n/{lang}/{module}.json`，
以**中文原文为 key**（正文按段落抽取，做不到语义 key），由 `postbuild` 合并进
`dist/data/knowledge-i18n/`，缺失自动回退中文。

- 改了 `crates/core` 里的中文句子 → 必须同步改 key，否则译文静默失效（页面仍是中文）；
  `cargo make knowledge-i18n-check` 专门守「key 漂移」，已并入 `cargo make check`；
- 工具：`knowledge-i18n-inventory` / `knowledge-i18n-missing` / `knowledge-i18n-add` /
  `knowledge-i18n-coverage`；
- 界面文案（本文件主线）与正文译文**不要混用目录**。

## 13. 明确不做 / 延后

- **性别（性数一致）**：西语的性数一致作用在**修饰语**上（`1 pregunta nueva` / `2 preguntas nuevas`），
  取决于名词的语法性别而非数字，需要给词条挂 `gender` 元数据；而本项目文案几乎都是「N + 名词」的
  短串，没有真实痛点（复数部分 `pregunta` / `preguntas` 已由 §4 覆盖）。**触发条件**：出现
  「N 个新的 / 已完成的 / 可用的 + 名词」这类带形容词的文案时再单独立项，用 `tg(key, gender)` +
  词条级 `gender` 元数据解决，**不并入复数系统**。
- **零值文案**：`共 0 题` 与 `暂无题目` 是措辞差异而非复数，用独立 key 解决，不进复数系统。
- **复数 / 性别规则里的精确小数位数 `v`**：当前三语只需区分「有无小数部分」，`Count` 因此只存布尔；
  接入需要精确 `v` 的语言（如 `ar`）时再改成 `u32`。
- **ICU MessageFormat / Fluent**、`tp` 接多个 count：见 §9 的取舍。
