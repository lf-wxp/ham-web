## 1. 已定决策

| # | 决策 | 含义 |
|---|---|---|
| D1 | **数据只有一份** | 领域逻辑、存储、接口、题目/知识数据全部共享，不存在「现代版数据层」 |
| D2 | **信息架构共享** | 路由、页面职责、URL、SEO、分享链接不变；差异只体现在呈现 |
| D3 | **像素风格冻结** | 像素 Kit 只做「原样抽取」，视觉零差异，此后不接受视觉改动 |
| D4 | **页面只写一次** | 页面组合语义槽，不产出类名、不产出布局容器；两套 Kit 各自渲染 |

D4 是成本能否收敛的关键：否则 179 个页面文件要写两份。

## 2. 「没有影子」的判定标准

下列 7 条全部可测/可查，作为每个阶段的验收口径（不是形容词）：

1. **类名零交叉**：`kit_modern/**` 与 `style/modern/**` 里不出现 `pxl-*`；只在像素风渲染的文件里不出现 `md-*`
   （两条都由 `check-structure` 的「双设计系统隔离」「反向隔离」守着）。
2. **token 零共享**：现代组件只用 `--md-*`，像素组件只用 `--pxl-*` / 既有语义 token。
   漏写一个变量时表现为「变量不存在」，而不是静默继承对方的颜色。
3. **DOM 零共享**：同一个语义槽在两套 Kit 里的标签结构可以完全不同（卡片是否有标题栏、
   列表是不是表格都由 Kit 决定）。
4. **图标/精灵不跨域**：现代 Kit 不可达 `IconKind` / `PixelSprite`（模块可见性隔离）。
5. **动效语言不混**：像素 `steps()` 与现代表情曲线各自在自己的 CSS 文件里，不互相覆盖。
6. **骨架不同**：导航形态、内容宽度、页面组成、移动端导航四者至少三项不同（§5 表）。
7. **切换即时且可持久**：`data-ui-style` 切换不需要刷新；刷新后保持；首屏无闪烁。

## 3. 架构：两套 Kit + 一份领域层

```
crates/app/src/
├── kit/                 语义槽的唯一入口（派发在这里发生，页面只认这里）
├── kit_modern/          现代实现：全新 DOM、全新技术类名（md-*）、全新动效
├── ui/                  共享基础控件：像素实现在这里，内部按 `kit::is_modern_at_mount()` 派发现代类名
├── pages/               页面；只换类名的区块用 `kit::*_class()`，要两套 DOM 的页面各写一份分支
> 原计划还有一个 `kit_pixel/`（把 `ui/` 迁进去）。**没有做**：`ui/` 一直作为像素实现保留，
> 现有门禁与文档都按这个结构写。下面的依赖图按原计划保留，读的时候把 `kit_pixel` 当成 `ui/`。
└── (core / data / store 不变)
```

**依赖方向**（`check-structure` 已有反向依赖检查，沿用它的思路）：

```
pages ──► kit ──► kit_pixel
              └─► kit_modern
kit_pixel ──► ui（迁移期）   kit_modern ──► 无像素依赖
```

- `kit/` 只允许依赖两套 Kit 与 `core`；不许依赖 `ui/`。
- `pages/` 不许直接依赖 `ui/`（迁移期有白名单，逐步清零）。
- `kit_modern/` 不许依赖 `ui/`、`icons/pixel`、`style/pixel`。

## 4. Kit 契约

槽清单（当前最小集，按页面需要增补；**新增槽必须两套同时实现**）：

| 槽 | 语义参数 | 像素实现 | 现代实现 |
|---|---|---|---|
| `Scaffold` | title / subtitle / actions / toolbar / children / aside | `PageHeader` + `PageContainer`（1200 单栏，与顶栏同宽） | 无页头标题栏：标题进正文流，1440 三栏 |
| `Card` | title / meta / href / actions / children | `SectionCard`（标题栏 + 2px 墨框） | 无标题栏：h3 + 描述 + hover 浮出操作 |
| `ModuleNav` | groups（3 组链接） | 阶梯下沉的三张卡片 | 三列分组链接 + 分隔线 |
| `Stat` | label / value / unit / trend | 像素铭牌 `pxl-badge` | 大号数值 + 上方小标签 |
| `ActionBar` | primary / secondary / hint | 固定底栏（`BottomBar`） | 主区内联 + 键盘优先 |
| `DataView` | columns / rows / mobile=cards | 宽表 + 横向滚动 | 列可配置 + 移动端卡片列表 |
| `Empty` | title / description / action | 精灵 + 框 | 纯文字 + 主按钮 |
| `Cta` | label / href / tone / size | `ButtonLink` | 现代按钮（圆角 + 软阴影） |

契约的硬性要求：

1. **参数只表达语义，不接受类名**：`class` 这类通道在两套 Kit 上必须被禁止（迁移期像素侧保留，
   现代侧实现为 no-op 并在评审中拒绝）。
2. **无障碍契约共享**：槽产出的可访问名 / role 必须一致，e2e 用 `getByRole` / `getByLabel` 定位，
   不因皮肤不同而改选择器（否则两套 e2e 无法复用）。
3. **页面不做订阅式派发**：`if style == …` 只有两种合法形态 —— 路由根 / 外壳的适配器，
   以及组件体里构造期求值一次的 `if kit::is_modern_at_mount() { return 现代实现 }`（§6、C7.6）。
   会随切换重跑的响应式闭包里用 `kit::is_modern()`。唯一禁止的是「组件体里读订阅版信号」，
   那会让 dev 构建按调用点数刷告警（`cargo make check-structure` 直接红）。
   迁移期页面确实是「一页两实现」的形态（首页即样板），D4「页面只写一次」是 S3 迁到语义槽之后
   的目标，不是今天的现状。

## 5. 两套实现允许差多远

同一份数据、同一条 URL，允许并鼓励下列差异（这是「没有影子」的来源）：

| 维度 | 像素（冻结） | 现代 |
|---|---|---|
| 桌面导航 | 顶部 64px HUD 横栏 + 三段下拉 | 56px 细顶栏 + 单一入口面板 |
| 移动导航 | 折叠面板 + 底部 5 Tab | 悬浮 dock + 全屏面板 |
| 页面组成 | 卡片流（标题栏卡片纵向堆叠） | 电波带首屏 + 数据条 + 大小不一的行动卡 + 三色模块卡 |
| 卡片解剖 | 标题栏 + 2px 墨框 + 零投影 | 无标题栏 + 10px 圆角 + 1px 墨线 + `shadow-1` + 单一高饱和焦点 |
| 表格 | 93 处宽表 + 横滚 | 响应式：桌面表格 / 移动卡片 |
| 反馈 | 像素窗 Toast，逐帧 | 右下堆叠，滑动关闭 |
| 动效 | `steps()` 逐帧、2px 位移 | 平滑曲线、悬停上抬、共享元素过渡 |
| 图标 | 24px 像素网格（`icons/pixel`） | 1.8px 线性描边、24 网格（`kit_modern/icons.rs`，两套资产不共用） |
| 游戏化 | HP/XP/金币/连击、精灵 | 等级环 / 连续天数 / 经验，无 HUD、无精灵 |
| 字体 | Fusion Pixel + Press Start 2P | Bricolage Grotesque（展示拉丁）+ Noto Sans SC 900（展示汉字）+ Geist（正文）+ IBM Plex Mono（读数 / 标签）+ 现代中文黑体（正文回落：PingFang / HarmonyOS Sans / MiSans / 思源黑） |

**版心宽度不在差异清单里**：两套皮肤共用 `--page-max`（1200px，定义在 `style/input.css`），
像素风的 `max-w-5xl` 与现代风的 `--md-page-max` 都指向它，顶栏 / 页头 / 正文 / 页脚同宽
（细节见 [`pixel.md`](pixel.md) §4 与 [`modern.md`](modern.md) §3）。切风格时版心不跳。

**现代风的设计语言：电波编辑部（Broadcast Editorial）**，四条原则：

1. **暖白纸面 + 深墨**：底色 `#f7f5f0` 而不是后台常用的冷灰；层级靠留白与字号，不靠灰字。
2. **一个焦点**：品牌橙的**实心块**只出现在首屏主 CTA 与「继续学习」这一张实心卡上；其余表面一律安静（白卡 / 深卡 / 浅色描边卡各一张）。
   橙色还可以标**位置**（「我在哪」：顶栏当前页的橙字 + 细轨道、dock 当前项的 8% 橙底），但那是文字 / 轨道 / 极浅底，不铺实心；**选中态**（多选项勾选、筛选 chip）一律用蓝，不用橙 —— 三条分清楚，「行动 / 位置 / 选中」才不会读混。
3. **大字号 + 克制的字距**：标题 `clamp(36px, 5.6vw, 72px)`；**中文一律不压负字距**（会挤字），只有数字/等宽读数保留 `-0.03em ~ -0.05em`。正文 16px / 1.75。中文靠字重与字号拉层级，因为 Geist 有 100–900，不存在像素风「没有粗体」的限制。
4. **电波母题**：首屏底部一条平滑曲线（橙→蓝渐变、两端淡出）替代边框与分栏；三色（橙 / 蓝 / 绿）分别对应考试、知识、工具，只做浅底与描边，不铺满。

不允许的差异：路由、页面职责、数据口径、文案 key、无障碍语义。

**弹层不合并成一份实现（2026-11-01 评估后决定不做）**：`ui::Confirm` / `MessageDialog` 的现代皮肤是组件体内
`if modern { return … }` 派发到 `kit_modern::ModernConfirm` / `ModernMessage`；`ui::Dialog` 则是同一个组件里按风格换类名
（`md-dialog-panel` / `pxl-popover`）。它们功能正常，合并只是纯重构、没有可见收益；而弹层是 e2e 覆盖最薄的一块
（评估时只有寥寥几条交互路径的用例），风险大于收益。真要合并，先补弹层的交互用例，再动实现 —— 记在这里是为了不让下一个人重复发现、重复评估。

## 6. 泄漏防线与门禁改造

| 通道 | 防线 | 落点 |
|---|---|---|
| 类名 | 现代只用 `md-*`；像素只用 `pxl-*` | 新增 `ui_check` 规则，按目录分域（见下） |
| token | `--md-*` 与 `--pxl-*` 两套；现代 CSS 自校验变量完整性 | `style/modern/tokens.css` + 构建期检查 |
| 全局一刀切规则 | 像素的零圆角 / 禁模糊 / 抖动底纹 / 星空 / `font-synthesis:none` 收进 `[data-ui-style="pixel"]` | `style/pixel/surfaces.css` |
| 图标与精灵 | `kit_modern` 模块私有，不 `pub use` `IconKind` | `kit_modern/mod.rs` |
| 字体 | 现代不引用 `--font-pixel-*`（顺带省掉 CJK 分片下载） | `style/modern/tokens.css` |
| 首屏 | `#boot` / `#fatal` 的内联样式按 `data-ui-style` 分支 | `crates/app/index.html` |
| 门禁 | 见下表 | `crates/tools/src/ui_check.rs` |

`check-ui` 的改造方式（**规则加作用域，不放松规则**）：

| 规则 | 现状 | 改为 |
|---|---|---|
| ⑤ 圆角、⑪ 字重、⑫ 缩放、⑭ 焦点环、㉓ 图标尺寸 | 全仓 `.rs` | 只对 `pages/**` 与 `kit_pixel/**` 生效 |
| ② 原生表单元素 | 排除 `ui/` | 再排除 `kit_modern/`（它自己就是一套控件层） |
| ⑧ 页面级宽度清单 | 全站一份 | 按风格两份清单 |
| 新增 | — | `kit_modern/**` 出现 `pxl-` / `--pxl-` / `border-ink` → 红 |
| 新增 | — | `pages/**` 出现 `pxl-` 外观类 → 红（迁移期用白名单递减） |

## 7. 风格开关

沿用仓库既有的偏好落地方式（`<html data-*>` + 首屏内联脚本 + 上下文），新增一个维度：

```
localStorage["ui:uiStyle"] = "pixel" | "modern"     ← 默认 pixel（D3：像素是基线）
        │
        ├─ index.html 首屏脚本 → <html data-ui-style="modern">
        ├─ theme.rs::DisplayPrefs::{ui_style, set_ui_style}（先写属性，后写信号）
        ├─ style/input.css → 现代样式层的启用条件
        └─ kit::is_modern() → 组件派发
```

约定：

- 派发读信号有两条口子，按位置选：
  - 组件体里 `if kit::is_modern_at_mount() { return 现代实现 }` —— 构造期求值一次，
    **不订阅信号**（在那里订阅只会得到一条「在跟踪上下文之外读信号」的 dev 告警，
    组件体也不会因此重跑）；
  - `view!` 属性闭包 / `move ||` 里用 `kit::is_modern()` —— 订阅信号，让那块内容随切换重渲染。
- **判断标准是「这行代码会不会被重复执行」，不是「想不想订阅」**：`let modern = …`、
  `class=if modern {…}` 这类一次性求值的位置一律用 `_at_mount`；只有真会随信号重跑的闭包
  才用订阅版。误用订阅版不会让界面出错，但 dev 构建会为**每个**这样的调用点刷一条
  `At crates/app/src/pages/bestiary/bestiary_page.rs:96:10, you access a RwSignal<UiStyle>
  outside a reactive tracking context` —— `kit::is_modern` 与 `DisplayPrefs::is_modern` 都带
  `#[track_caller]`，告警里的位置就是**真正的调用点**，照着改那一行，别改 `theme.rs`。
- 守卫三处，各管一段（三处都过才叫不会漏）：
  - `cargo make check-structure`「组件体里订阅风格信号」：**函数体顶层（rustfmt 的 2 空格缩进）**
    出现 `kit::is_modern()` 直接红（C7.6）—— 只看缩进，判不出「藏进 `let x = { … }` 块」的写法；
  - 同一守卫的「风格读取闭包被立即调用」：`let f = … || { … kit::is_modern() … };` 之后又出现
    `f()` 就红 —— `{f()}` 把闭包跑在组件体构造期（没有跟踪上下文），要么写 `{f}` 交给 `view!`
    渲染，要么把闭包里的读换成 `_at_mount`；
  - `e2e/tests/smoke.spec.ts` 把 Leptos 的「在跟踪上下文之外读信号」告警当失败 —— 只在 dev
    构建（`debug_assertions`）下有声，`cargo make e2e` 的 release 口径里空转，见
    [`docs/engineering/testing.md`](../engineering/testing.md)。
  仍有一种抓不到：把派发藏进一个在组件体里**通过别的函数**调用的包装函数（读信号那行既不在
  组件体顶层、也不在登记的闭包里）。
- 切风格后整页换皮肤靠的是 `app/main_content.rs` 重建整棵路由子树（两个分支的根元素类型不同），
  所以组件体里的构造期派发在切换时会被重新执行一次。页面里的组件必须挂在这棵子树下，
  否则切风格后会停在旧 Kit。
- 重建的代价是**页面内未持久化的状态会丢**（表单草稿、当前题号、滚动位置）。这是已知取舍：
  切风格是低频操作，而「切完停在半套皮肤上」是不可接受的状态。要保住的状态就存 `localStorage`
  （见 `docs/reference/storage.md`），不要指望组件活着。
- 因为子树会被重建，**打开着的弹层可能被卸载**：两套 Kit 的弹层副作用（滚动锁 `crate::overlay::use_scroll_lock`、
  焦点编排 `crate::focus::use_modal_focus`）都在 `on_cleanup` 里释放/归还，否则会出现「切完风格页面滚不动」
  「焦点丢到 body」。**这两个各只有一份实现，两套 Kit 的每个弹层都必须调用**：不要自己写
  `body.style.overflow`，也不要只补一个 Esc —— 少一样就是「键盘用户进不去」（`use_modal_focus`：打开聚焦面板 /
  Tab 循环 / 关闭归还焦点）或「切风格后页面滚不动」（`use_scroll_lock`：打开锁滚动、**卸载时释放**）。
  打开时的聚焦是**延迟一帧**发出的（面板这一帧才挂上），所以只在焦点还没进面板时才送：那一帧里
  用户已经在第二个输入框里打字时，抢回第一个输入框会把字送进别的字段。
- `#route-content` 里两套风格的根节点分别带 `data-style-root="modern"` / `"pixel"`：排查时用它
  确认「当前挂的是哪套根节点」（样式层与其他代码都不依赖它，e2e 判据用的是类名与 `data-ui-style`）。
  换页签名 `data-sig` **两套都会写**：
  像素风下那些规则必须自带 `html[data-ui-style="modern"]` 门禁，
  `cargo make check-structure` 的「现代风样式门禁」守着。

- key 属于 `ui:` 前缀，与「像素动效 / 易读字体」同族，**设备本地偏好、不参与远端同步**
  （`is_device_local_key` 已按前缀归类），但要登记到 `docs/reference/storage.md` 与
  `remote_sync.rs::every_documented_key_is_classified` 的 DEVICE 名单。
- 设置入口：两套 Kit 各有一个（像素用现有 `SettingsDialog`，现代用现代面板）——
  这本身就是「两套实现」的一部分。
- 默认值固定 `pixel`，不做设备自动选择：避免同一份文档/截图在不同设备上不一致。

## 8. 像素冻结怎么证明

> **原计划（截图基线）没有实施**：仓库里没有 `e2e/visual/`、`visual_pixel.spec.ts`，也没有
> `toHaveScreenshot` 用例；本节早先写的「28 张截图 diff = 0」从未发生过，已删除。

实际用的是可机械判定的替代：

1. **隔离**：`dual_isolation.spec.ts`（等挂载 + 正向对照 + 打开态表面必须出现）与 `e2e/audit/*.mjs` 全量扫描，
   证明两套皮肤互不串类名；
2. **规范门禁**：`check-ui`（像素风规范的「应为 0」条目）与 `check-structure`（隔离 / 门禁 / 断点 / 索引）；
3. **既有 e2e**：像素风是默认值，全部旧用例都在像素风下跑，行为回归由它们兜住。

它**证明不了**逐像素没变。若以后确实需要视觉基线，另起一节写清基线存放位置与更新流程再实施。

### 两套皮肤互不串的验证方法（完工判据）

判据（2026-11-01 实测，可复现）：任意页面 / 打开态表面，在任一皮肤下都不出现另一套皮肤的类名。

```bash
node e2e/audit/dual_sweep.mjs modern && node e2e/audit/dual_sweep.mjs pixel
node e2e/audit/surface_sweep.mjs modern && node e2e/audit/surface_sweep.mjs pixel
# 结果：181/181 页面；表面现代风 9/9、像素风 8/8（调谐台是现代风专有），两侧均为 0
```

## 9. 参考实现

| 范式 | 代表 | 借什么 |
|---|---|---|
| Skin / 模板系统 | MediaWiki（`SkinVectorLegacy` 与 `SkinVector22` 同仓两套实现，per-user 切换）；WordPress / Moodle / Discourse | 核心只暴露数据与 hook，skin 自带模板与 CSS；**skin 之间不共享选择器** |
| Headless 行为层 | Radix Primitives / React Aria / Ark UI / Base UI | 键盘、焦点、开合、ARIA 提炼成一层，两套呈现共用（对应 `kit/` 与 `ui/` 里那部分行为） |
| 版本化 DS 共存 | Fluent UI v8 / v9（shim + Provider 隔离并存）、Carbon v10 / v11（flag 灰度） | 开关 + 按模块分批迁移 + 期间两套并存 |
| 视觉回归 | Storybook + Chromatic 的等价物 | Playwright 截图基线（仓库已有 e2e 基建） |

反例（不要参考）：DaisyUI 30+ themes、MUI/Chakra theme、shadcn 主题变量 —— 同一 DOM 换 token，
布局与交互不变，正是本方案要避免的。

## 10. 不引入第三方组件库

结论：**不引入第三方组件库，继续在 `crates/app/src/ui/` 自维护**。理由：

1. **没有与本项目管线对齐的成熟实现**。shadcn/ui 官方只覆盖 React / Vue / Svelte，
   其「复制粘贴式组件」的精髓就是类名写在自己仓库里；Leptos 侧的移植项目
   （如 `leptonic`、各类 `leptos-shadcn` 尝试）要么自带一套与本项目 oklch Token 不兼容的
   主题体系，要么跟进 Leptos 版本滞后（`leptos` 0.8 的响应式 API 在 0.7 之后有破坏性变更）。
2. **可定制性**。本项目的 `cn()`（`src/cn.rs`）已经实现了 tailwind-merge 的冲突组覆盖，
   组件类名可直接被 `class` 覆盖；引入外部库反而要跨过它的样式封装层去改。
3. **体积与构建**。前端是 `wasm32` + `wasm-opt -z` 的体积优先构建，任何额外的
   组件依赖都会直接体现在产物大小上；而当前每个组件只是几十行 `view!`，编译期即展开。
4. **兼容性**。项目是纯 CSR（`leptos::mount::mount_to_body`），没有 SSR / hydration 约束，
   自维护组件的边界处理已经沉淀成共享实现：滚动锁在 `crate::overlay`，焦点与 Esc 在 `crate::focus`，
   退场卸载在 `crate::presence`，Portal 的用法见 `ui/dialog/`。

## 11. 视觉语言与字体的取舍

规则与取值在 [`modern.md`](./modern.md)；这一节只记**为什么这么定**，以及换方案时要重新权衡的备选项。
代码与 CSS 注释里「见 decisions.md §11.x」都指这里。

### 11.1 颜色：橙是「行动」，蓝是「选中」

五个角色（页面底 / 表面 / 描边 / 文字 / 行动）的取值见 [`docs/ui/modern.md`](./modern.md) §2.1，这里只留理由。

语义色固定：`--md-blue` = 选中（选项、当前题）、`--md-green` = 正确；错误与提醒走状态色 token
（modern.md §2.1「状态色」，组件里不写字面色值）。**橙色不是「高亮」，是「行动」**——不要拿它标选中态：
用橙标选中会让一屏出现多个「主行动」候选，主 CTA 也就不再是唯一焦点。

### 11.2 视觉语言：海报式版面

从「深色玻璃」转向**海报 / 编辑排版（Poster Editorial）**：靠字号、平面色块、墨线与留白
建立层级，不靠柔光、渐变与投影。这一节是判断「新加的样式算不算这套语言」的口径。

规则与取值已进 [`modern.md`](./modern.md) 与 CSS 注释；这里只留两条在别处找不到的理由：

- **边界即骨架**：分区一律 1px `--md-rule`（比 `--md-border` 更墨）；卡片 10px 圆角 +
  1px 描边 + `shadow-1`（平面化不等于没有厚度：浅色下只靠 1px 会糊成表格）；
  「大容器 + 柔光 + 玻璃」不再出现。
- **渐变的唯一开口**：只允许出现在「不承载文字的实心几何面」上，且只有两种用法 ——
  同色相双档过渡（`--md-face-a` / `--md-face-b`），或用两段硬切（`0 50%` / `50%` 到
  transparent）**切出一个三角**（章节标头、模块卡角标就是这条）。它不是「渐变效果」，
  是画形状的工具，边界是硬的。多色柔光、彩色光斑、渐变标题一律不做。

### 11.3 几何语言：六族记号与三条硬规则

首页那套几何（圆 / 三角 / 斜切 / 网格 / 刻度）不是首页专属。它按**页面元素层级**生效：
同一个元素在哪个页面都长一样 —— 所以「延伸到全站」不是逐页加样式，而是给共用组件与
骨架加规则，新增页面自动继承，不用再写 CSS。

| 记号 | 语义 | 落地 |
|---|---|---|
| 同心圆 | 波前 / 方向图 | 首屏底盘（1px 实线 + 虚线内圈 + 竖轴）、主 CTA 卡右下角 |
| 直角三角 | 指向 / 层级 | 章节标头、模块卡角标、`md-panel` / `md-stat` / `md-term` 角标、目录项前导 |
| 45° 斜切 | 扫描 / 时间带 | 首页 7 日瀑布格 |
| 正交网格 | 坐标纸 | 内容型页面的 `.md-page::before`（≥900 才画） |
| 刻度尺 | 频率 / 电平轴 | 页头下沿右端、章节上沿右端、数据条分栏 |
| 竖线 | 连接 / 分栏 | 清单节点链、数据条分隔 |

1. **几何不承载信息**：全部落在伪元素 / `aria-hidden` 装饰与背景层上，删掉 CSS 后功能与
   文案一字不少。唯一的「形状 + 颜色」双编码是首页波段电平柱（高度 = 档位、颜色 = 档位），
   因为色觉障碍用户需要形状维度。
2. **不新增色相**：角标取容器的 `--tone`（缺省回落到 `--md-accent`）；刻度只用
   `--md-rule` / `--md-border-strong`。
3. **像素风零影响**：所有规则都在 `html[data-ui-style="modern"]` 或 `.md-*` 前缀之下。
   像素风页面不渲染 `md-page-head` / `md-panel` / `md-stat`，拿不到任何几何记号。

### 11.4 令牌：圆角阶梯与间距的历史值

现代风的样式是**三层**：基础值（`tokens.css`）→ 语义（少量场景名）→ 组件（只消费 token）。
组件里出现裸 px 时，同一个「看起来一样」的间距会在不同组件里漂成 9 / 10 / 12 三档，
改一次布局要全文件搜索。取值本身见 `tokens.css` 与 [`docs/ui/modern.md`](./modern.md) §2.4；这里只留圆角阶梯和两条取舍。

**圆角**：六档，每档一个场景（取值见 [`docs/ui/modern.md`](./modern.md) §2.4）。

- `--md-r-xs`：内嵌细条（进度槽、色条、代码标记）；
- `--md-r-sm`：chip / tag / 小按钮；
- `--md-r-ctl`：可交互控件（输入 / 下拉 / 按钮 / 文本域），`--md-control-r` 指向它；
- `--md-r-md` / `--md-r-lg`：卡片 / 面板 / 列表容器（`md` 是历史别名，与 `lg` 同值，新代码用 `lg`）；
- `--md-r-xl`：大容器 / 弹层 / 抽屉 / 首屏读数条；
- `--md-r-pill`：胶囊与圆点。

例外只有四种：`0`、`50%`（正圆）、`inherit`、`calc(...)`（跟随尺寸的徽记）。

**门禁**：`check-ui` 扫 `style/modern/` 下的全部 CSS（`tokens.css` 是阶梯的定义处，不扫），`border-radius` 出现裸 px 直接红。

**间距：10 与 14 是历史值**——`--md-space-2-5`（10px）与 `--md-space-3-5`（14px）仍在使用，但新代码不要再选。
归并方向 —— 堆叠间距 10→12、行内间距 10→8、区块间距 14→16、控件内 14→12。做归并时要一起看 `i18n_layout`
（英文/西语文案更长，收紧 2px 可能触发文本裁剪）。

**为什么间距不进门禁**：圆角已经进 `check-ui`；间距暂不进门禁 —— `padding` 的双值组合场景太多（控件 / 卡片 / 内嵌条），
一刀切会逼出大量 `!important` 式的例外。新代码按 `tokens.css` 的阶梯写，评审时看。

### 11.5 字体：为什么是这三支

**问题**：展示 / 正文 / 等宽三层原先都由 Geist 一支承担。层级只靠字号与字重拉，
读起来是「Vercel 后台的默认字」—— 与 §11.2 的海报式版面（实心色块、墨线、两位编号、
刻度尺）不是同一套语气：**版式是编辑的，字面是工具的**。

**方案**：把「谁说话」拆成三个声部，每个声部一支字，各自只在自己的音域出现。

| 声部 | 字族 | 音域 | 定位 |
|---|---|---|---|
| 展示 | **Bricolage Grotesque**（可变 `opsz 12–96` / `wght 200–800`）+ **Noto Sans SC 900**（汉字） | ≥26px：首屏主张、文章页 h1、区块 h2、行动卡标题、品牌字 | 海报标题声部。拉丁是法国海报体谱系（字口略窄、竖笔末端斜切，大字号自动收紧），汉字是自托管的思源黑体 Heavy |
| 正文 | **Geist**（`100–900`） | 14–22px 的一切 | 正文声部。界面里最安静的一层 |
| 辅助 | **IBM Plex Mono**（400 / 500 / 600） | 10–13px 的编号 / 读数 / 标签 / `kbd`；表格里的频率与时间 | 仪器声部。方形字碗 + 折线端头，与「深色电波」同源 |

声明在 `style/modern/fonts.css`（拉丁三支）与 `fonts-cjk.css`（中文字，生成物），取值在 `tokens.css` 的 `--md-font-{display,mono}`；
谁用哪支的速查表在 [`docs/ui/modern.md`](./modern.md) §2.2。

#### 搭配逻辑（为什么是这三支）

1. **同谱系、不同音域**：两支无衬线都是 grotesque，x-height 接近（Bricolage 0.528 /
   Geist ≈0.53），并排时基线不打架；差异来自字口宽度与笔画端头，不来自气质 ——
   不是「黑 + 宋」那种对撞。
2. **展示字族有 `opsz` 轴**：36px 与 72px 拿到的是两套字口，而不是同一个字形放大。
   这是它比「换一支更粗的无衬线」更值钱的地方。
3. **正文必须安静**：正文换字族是收益最低、风险最高的一步（179 条路由 × 三语 × 中英混排），
   所以 `--md-font` 留在 Geist，把辨识度交给标题层与辅助层。
4. **辅助层是最划算的一层**：界面里到处是等宽小字（章节编号 `01/02`、频率、日期、来源、
   数据条标签），而中文界面里的西文字形几乎**只**出现在这一层 —— 换它，中文用户也能
   一眼看出「字变了」，且不碰任何正文可读性。
5. **汉字自带 900**：Bricolage 与 Plex 都没有汉字。汉字如果继续回落系统黑体，
   中文标题就只换了字号 —— 因为这层系统字体**给不出更重的字重**（PingFang SC 最高
   Semibold、微软雅黑最高 Bold，`font-weight: 780` 会被就近匹配回 600）。
   所以展示层自带一支思源黑体 Heavy（见「中文展示字」一节），汉字与拉丁同属
   grotesque 谱系，只是一个更重、一个更窄。
   栈序即分工：拉丁命中 Bricolage → 汉字命中 Noto → 两者都不认识的生僻字才落到系统黑体。

#### 音域的护栏

- 展示字族**只在 ≥26px 出现**：它在 13px 控件标签里比 Geist 更「有主张」，会抢层级
  （实现上 `.md-mod-title` / `.md-panel-title` 是 24px 也用展示字族，是对这条的小幅放宽）；
- 等宽最小 10px，**只做标签不做段落**。

#### 平台差异：只剩正文汉字

Windows 没有 PingFang / MiSans，落到雅黑；Linux 落到思源黑或 Noto。拉丁三支与**展示层汉字**全部自托管，
所以标题在三端完全一致，只有正文汉字随系统 —— 这是当前成本下的最优解
（正文也自带 CJK 至少再多 1–2MB，且题面用字量远超界面文案）。

#### 备选方案与切换成本

| 想要的语气 | 展示换成 | 代价 |
|---|---|---|
| 更克制、更工业 | **Archivo**（可变 `wdth 62–125`） | 海报感弱一档；宽度轴可以做出「展开的报头」 |
| 更强的编辑感 | **Instrument Serif** | 拉丁标题与中文黑体对撞，慎用；所有展示级尺寸都要重核行高 |
| 更技术、更窄 | **Space Grotesk** | 与 Geist 差别偏小，容易被读成「没换」 |

等宽备选：**JetBrains Mono**（点零 + 连字，代码感更强）、**Martian Mono**（更宽，
适合纯标签，不适合表格列）。换哪一支都只改 `tokens.css` 里的一行 + `fonts.css` 的
`@font-face`，不动任何组件。

#### 中文展示字：为什么是思源黑 900

**选型**（三款都实测过子集体积与屏幕效果）：

| 候选 | 结论 |
|---|---|
| **Noto Sans SC 900（思源黑体 Heavy）** ✅ | 字面仍是黑体，不改风格；补上的正是系统黑体给不出的那一档字重；三端字面一致 |
| 思源宋 900 | 编辑感最强（宋体标题 + 暖纸底很像杂志），但会把「仪器面板」的气质推向「出版物」，属于换风格 |
| 得意黑 | 辨识度最高，但自带 7° 倾斜 —— 与未倾斜的拉丁同排时一半斜一半正，标题里只要有 `DXCC` / `FT8` 就露馅 |

**字重只有一个 900**，展示层里 740/760/780 的差异对汉字不再生效 —— 层级由字号承担，
这正是 §11.2「靠字号与留白」的口径；拉丁仍可按 `wght` 微调，因为 Bricolage 是可变字体。
