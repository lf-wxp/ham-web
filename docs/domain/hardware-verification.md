# 真机验收清单

这份文档只回答一件事：**哪些功能只有协议层测试、还没在真机上跑过**，以及要怎么把它跑通。

单元测试（`core/cat.rs`、`core/rotor.rs`、`core/vna.rs` 等）保证的是「字节拼得对、帧能解析」；它保证不了「这台机器真的是这么回的」。两者不能互相替代。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| **已验证** | 真机跑过，并且记录了型号、固件版本、串口参数、日期与实际现象 |
| **待验** | 有硬件或能借到，但还没跑 |
| **无硬件** | 明确缺什么设备；不允许写「应该可以」 |

判定一条「已验证」的最低要求：能贴出下面这份记录里的每一项。**只有单测 / 假串口通过，一律算「待验」**。

## 验收记录模板

```text
功能：卫星上行写入（另一个 VFO）
日期：2026-11-02
电台：Yaesu FT-991A，固件 1.900
串口：/dev/cu.usbserial-1420，38400 8N1，协议 = Kenwood ASCII
步骤：下行自动调谐 → 勾选上行 → 观察 VFO B
结果：命令 `FB` 生效，VFO B 频率跟随；未触发发射；未改分频
差异：无 / 见 ROADMAP 某条
```

## 维护规则

1. 跑通一条：把状态改成「已验证」，补记录；**同时**更新 `ROADMAP.md` 对应条目的「已知边界」。
2. 发现行为与预期不符：先改文档（写清差异），再决定是改代码还是改护栏；不要只改代码不留记录。
3. 新增串口功能：先在本文件加一行（哪怕状态是「无硬件」），再写代码。
