# 用 fldigi 自己的收发端验证（fldigi-web）

[`crashdemons-external/fldigi-web`](https://github.com/crashdemons-external/fldigi-web) 把 **fldigi 4.2.13 的原版调制解调器**
编译成了 WebAssembly（`web/fldigi-core.wasm`）。下面的 Node 脚本直接调用它的 API，不经浏览器：

| 脚本 | 做什么 |
| --- | --- |
| `gen.mjs <模式> <文本> <中心 Hz> <输出.wav>` | 用 fldigi 的**原版发端**生成一段完整发射（含前导与收尾）；`node gen.mjs list` 列出 MFSK / THOR 模式名 |
| `dec.mjs <模式> <输入.wav> <中心 Hz>` | 用 fldigi 的**原版接收机**解码（末尾补 6 秒静音，让管线里压着的字符流出来） |
| `gen_pic.mjs` / `dec_pic.mjs` | 图片模式的发端 / 接收机（包了它的 `_web_tx_image_*` 与 `_web_take_image_updates`；MFSK 与 THOR 共用「尺寸序号」格式） |
| `gen_all.sh <目录>` | 一次生成全部 MFSK / THOR 子模式的 `fw_<模式>.wav`、四条长录音 `fwlong_*`（同一报文重复 8 遍，45–175 秒）与图片录音 `fwpic_*`（`.rgb` 是原图） |

```text
git clone --depth 1 https://github.com/crashdemons-external/fldigi-web /tmp/fldigi-web
FLDIGI_WEB=/tmp/fldigi-web sh gen_all.sh /tmp/fw
MFSK_REAL_DIR=/tmp/fw cargo test -p ham-web-mfsk --release --test real_recordings -- --include-ignored
THOR_REAL_DIR=/tmp/fw cargo test -p ham-web-thor --release --test real_recordings -- --include-ignored
```

`FLDIGI_WEB` 必须显式设置：所有 `.mjs` 脚本与 `noise_sweep` 都不再有默认目录（默认放在 `/tmp` 等于加载并执行任何人都能写的目录里的代码）。

fldigi 的 GitHub 镜像（`w1hkj/fldigi`）停在 2022 年的 4.1.23，没有 THOR25 / 32 / 44 / 56；本目录以 fldigi-web 随附的 4.2.13 源码
（`vendor/fldigi/src/`）为准，两边在共有的模式上完全兼容。`../fldigi_ref.cpp` 与 `FLDIGI_SRC` 的逐位对拍仍用镜像。

## 双向验证（全部子模式）

- **fldigi 发端 → 本仓收端**：两个 `real_recordings` 测试。11 个 MFSK 子模式（含 5 位符号的 MFSK4 / 8、3 位符号的 MFSK31 与长交织的 64L / 128L）与
  15 个 THOR 子模式（含 K = 15 的 25 / 25x4 / 50x1 / 50x2 / 100）全部逐字解出，中心频率自动检测都落在 1/8 音调间隔内。
- **本仓发端 → fldigi 收端**：`generate_sample` 示例生成的音频喂给 `dec.mjs`，MFSK4 / 8 / 16 / 31 / 32 / 64 / 128 与
  THOR micro / 4 / 8 / 16 / 25 / 32 / 44 / 56 / 25x4 / 50x1 / 50x2 / 100 全部被 fldigi 的接收机还原出报文。

## 模式参数

**长交织变体 64L / 128L**：深度 400 / 800、冲刷 2500 / 5000 位，**发端不发 `preamble / 3` 个前导零位**（fldigi `mfsk.cxx` 的 `tx_process` 专门排除了这两个模式）。
音调序列对 fldigi 上游代码逐位相同（`upstream_xcheck`）。**fldigi 自己的接收机在正文前面也会吐出一串乱码**（`q tRneVh$rpe tcrt…`）：没有前导零位，
信号头 `(符号位数 − 1) × 深度` 个符号里反交织器还没填满，译出的是发端从未发过的「发送前历史」；本仓收端把这一段丢掉。
和别的模式不一样的几处（原因写在 `Mode::long`、`front::POLISH_REACH_LONG` 与 `rx.rs` 的 `CWI_OFF` 注释里）：整段录音只用到
0 / 1 / 3 / 7 / 15 五个音调且九成以上是最低音调，粗检测会偏 5–7 个音调，要靠对齐后的核对拉回来；信号头有连续十来个同一音调，窄带干扰检测不能开；收端不补冲刷。

**THOR25 / 32 / 44 / 56**（参数取自 4.2.13 的 `thor.cxx`）：

| 模式 | 采样率 | 符号长 | 间隔 | 深度 | 冲刷 | 卷积码 |
| --- | --- | --- | --- | --- | --- | --- |
| THOR25 | 8000 | 320 | 1× | 25 | 20 | **K = 15**（与 25x4 / 50x1 / 50x2 / 100 一起选 K15，不是名字看起来的慢速 K = 7） |
| THOR32 | 8000 | 256 | 1× | 10 | 20 | K = 7 |
| THOR44 | 11025 | 256 | 1× | 10 | 4（默认值） | K = 7 |
| THOR56 | 16000 | 290 | 1× | 10 | 20 | K = 7 |

THOR56 的符号长 290 在 16 kHz 下不是整数个周期，波特率 55.17 Hz，窗口按小数位置落点。

**MFSK4 / 8 的交织深度**：fldigi 4.2.13 是 5，gMFSK 官方样本是 10，两种都试（路径度量择优，见 `rx.rs` 的 `depth_wins`）。

## 弱信号与窄带干扰（差分对拍）

没有「正确答案」的真实弱信号样本时，`crates/thor/examples/noise_sweep.rs` 把**同一段**加了噪声 / 载波的音频同时喂给
fldigi 4.2.13 的接收机（`dec.mjs`）和本仓解码器（进程内直调 `ham_web_thor` / `ham_web_mfsk` 的 `decode_audio`，
`--family` 切换），数各自解出多少遍完整报文（每个点 3–4 个种子；报文重复 8 遍；噪声是高斯白噪声，
SNR 是信号总功率 / 噪声总功率，全带宽）：

```text
cargo run -p ham-web-thor --release --example noise_sweep -- --family thor --mode 16 \
    /tmp/fw/fwlong_THOR16.wav --snr -12 -13 --seeds 4
cargo run -p ham-web-thor --release --example noise_sweep -- --family thor --mode 16 \
    /tmp/fw/fwlong_THOR16.wav --snr -5 --seeds 4 --cw 1550 --cw-db 3
```

加噪与打分复刻了 CPython `random` 的 MT19937 与 `gauss`、`difflib.SequenceMatcher`（复刻的正确性由 example 里的三个单测钉住），
同一命令两边给出的表逐点一致。加噪样本先落成 16 位 PCM 再读回：弱信号下噪声幅度是信号的好几倍，写盘会大量削顶，
不落盘会让本仓这边明显偏乐观（THOR16 −13.5 dB：不落盘 31 / 32 遍，落盘 12 / 32 遍）。
没装 node 或没克隆 fldigi-web 时加 `--skip-fldigi`，只跑本仓那一列。

| 场景（完整遍数，括号里是满分） | fldigi 4.2.13 | 本仓 |
| --- | --- | --- |
| THOR16 白噪声 −12 / −12.5 / −13 / −13.5 dB（各 32） | 27 / 15 / 4 / 0 | 32 / 30 / 20 / 12 |
| THOR100 白噪声 −4 dB（16）、THOR8 −16 dB（16）、THOR25 −12 dB（16） | 2、0、0 | 14、13、3 |
| THOR16 + 载波 0 / +3 / +6 / +12 dB（信号功率的倍数，SNR −5 dB；各 24） | 0 / 2 / 2 / 0 | 24 / 19 / 19 / 8 |
| MFSK16 + 载波 0 / +6 / +12 dB（同上；各 24） | 0 / 0 / 0 | 24 / 24 / 7 |

- **白噪声下本仓不输 fldigi**（离线有整段录音，符号对齐 / 频率只搜一次，比 fldigi 的在线同步强）。THOR 因此不做软位路径
  （`softdecodesymbol`）：没有量到差距，它的软值来自子频点上的载频偏差，本仓的 Goertzel 网格里没有这个量。
- **恒定载波（窄带干扰）下 fldigi 几乎全军覆没**：载波与信号等功率时它一遍也解不出。本仓的做法见 `ham_web_mfsk::front::suppress_carriers` /
  `erase_strong_carriers`；载波比信号强 12 dB、同时噪声又大时也解不出（MFSK16 7/24、THOR16 8/24）。
- **前导检测（`THOR_PREAMBLE`）不做**：两段发射之间隔 3 秒噪声的录音，本仓与 fldigi（默认开着前导检测）解出的正文逐字一致，没有可量出的差距。

## 图片模式

三层验证：①fldigi 4.2.13 **桌面版的真实录音**（fldigi-web 的 `tests/fixtures/fldigi-picture-{mfsk16,thor16,thor25}.wav`）；
②**fldigi 原版发端**发的图片逐字节与原图比，同一段音频再喂 fldigi 自己的接收机（`dec_pic.mjs`）对照；③本仓自己的发端往返。
门限分别在 `crates/{mfsk,thor}/tests/real_recordings.rs`、`tests/picture.rs`。**只在模式的标称采样率上解图**，别的采样率只给文本。

**MFSK（16 / 32 / 64 / 128，`Pic:<宽>x<高>[C][p<2|4|8>];` 报头）**

- 真实录音（MFSK16，32 × 24 彩色四块纯色）：四个象限中心与预期相差 ≤ 1（fldigi-web 自己的测试要求 ≤ 2），自动检测与手给 1500 Hz 都对。
- fldigi 发端的 6 张图（MFSK16 / 32 / 64 / 128、彩色 / 灰度、`bands` / `ramp`）平均误差：本仓 6.6 / 18.3 / 12.5 / 5.9 / 2.7 / 5.7，fldigi 接收机 7.1 / 20.9 / 11.3 / 4.6 / 15.7 / 6.6，
  同一量级（误差来自 FM 带宽有限、像素间的大跳变被抹圆）。
- **图像起点**：报头最后一个字符（`;`）补完的符号窗口结束处，加 `(冲刷符号数 − 流水线延迟) × 符号长 + 352 个样本的序言`
  （冲刷 = `(preamble + 1) × 2 / 每符号位数`，延迟 = `3 × 深度 + 24` 个符号），与 fldigi 在 `recvchar` 里硬编码的启动延迟一致
  （MFSK16 / 32 是 352，MFSK64 是 4956，MFSK128 是 1824）；对 fldigi 发端的图片，比最佳位置偏 −2 ～ +4 个样本（半个像素以内）。
- **图像前后是两段独立的 MFSK**：整段录音全局对齐的符号偏移与图像之前那一小段可差 144 个样本，所以起点用图像之前那一小段重新对齐后的窗口来推，
  中心频率也取这一小段的（整段里夹着图像时，时钟 / 频漂跟踪会把图像段当信号去拟合，MFSK64 实测拟合出 +30 Hz）。
- 自动检测中心频率会被图像里的调频窗口带偏（斜坡图可偏 3 个音调）：译文不像人话且没图时，退一步只用录音开头 30% / 50% 重估。

**THOR（11 / 16 / 22 / 25 / 32 / 44 / 56，`pic%<码>` 报头）**

- 真实录音（THOR16 / THOR25，59 × 74 彩色四块纯色）：四个象限中心与预期相差 ≤ 1，整幅图平均误差 1.98 / 1.13（fldigi-web 的要求：≤ 2 与 < 3），自动检测与手给 1500 Hz 都对。
  测试里的「预期图」判左右半必须用浮点比较（`x < 59.0 / 2.0`），整数除法会让第 29 列错判、整幅图误差多出 1.5。
- fldigi 发端的 10 张图（`fwpic_t*`）平均误差：

  | 录音 | t16 bands | t16 ramp | t16 灰度 ramp | t25 | t32 | t11 | t22 | t44 | t56 | t16 120 × 150 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | 本仓 | 2.0 | 8.0 | 2.6 | 5.0 | 4.1 | 14.0 | 4.1 | 4.6 | 8.0 | 7.5 |
  | fldigi 接收机 | 2.2 | 32.5 | 8.9 | 39.2 | 23.4 | 40.7 | 32.3 | 21.8 | 32.5 | 30.4 |

  斜坡图上 fldigi 的在线同步经常错位，差距集中在 ramp 上；纯色块图两边相当。
- **做法**：整段 Viterbi 对含图像的录音会因「非法半字节占比」检验直接判无信号，所以先在整段录音里找同步音
  （`[中心 − 0.8 × 带宽, 中心 − 0.48 × 带宽]` 内恒定、≥ 8 个符号长），中心频率 = 同步音频率 + 0.6 × 带宽（与真实中心差 < 0.001 Hz，比文本里音调梳的检测准）；
  同步音之前的文本照常解、取最后一个报头；图像从同步音结束处解（低通截止 = 带宽）；之后的录音用同一个中心频率递归。

## 漂移跟踪

**验证**：四条长录音（`fwlong_MFSK16` / `MFSK32` / `THOR8` / `THOR16`）用重采样加上漂移——常数时钟误差（+1000 / −1500 ppm）与时变转速
（80–90 秒里符号边界偏出约一个符号、带出 ±0.03–0.05 Hz/s 的频漂）——断言 8 遍报文逐字都在、估到的平均时钟误差与实际拉伸相差 < 150 ppm。
对照（把 `track` 关掉）：MFSK16 / THOR16 在 +1000 ppm 下只剩 7 / 6 遍，−1500 ppm 下 6 / 4 遍；加噪声后更差。

**边界**（本仓发端合成的干净信号，没有拿 fldigi 的接收机对比；MFSK16 / 8 / 32，8 遍报文）：

- **时钟跳变**（中途丢 / 插样本）：20 / 100 个样本 8 / 8 遍，300 / 1000 个样本 7 / 8（含缺口的那一遍丢了符号，是下限）。
- **突然跳频**（在录音 20% / 50% / 80% 处）：跳 ±0.1～0.5 个音调间隔全部 8 / 8；跳 +0.6 / +0.8 / −0.8 个间隔只剩 3～6 遍——
  这已经不是漂移，而是整个音调序号错了一位、边缘音调落到梳外面；恰好 ±0.5 是平手，偶尔判错。
- **短录音 + 大时钟误差**（MFSK 16 / 32 / 4 / 8 / 64 × 1 / 2 / 3 / 6 遍 `CQ CQ DE BG1AAA K ` × ±1000～12000 ppm，共 160 格）：151 格全对，
  余下 9 格全是 ±12000 ppm 的长录音（块内漂移 0.58 个符号，块太长）。机制：块长随录音缩短（`track::block_len`），估出 ≥ 1500 ppm 就重采样回名义时钟再解一遍（`undo_clock`）。
  不做这两条时，MFSK16 / 32 的 10 秒以内录音从 ±12000 ppm 起乱码，MFSK4 的 33–58 秒短报文从 3000 ppm 起乱码。
- **THOR 不需要重采样**：差分编码下频率整体缩放不改变音调之差，THOR4 / micro 的 34–90 秒短报文在 ±3000～12000 ppm 下关掉重采样也全对。

## 短报文的中心频率与交织深度

MFSK 的发射总是以最低音调（符号 0）的恒定前导开头、以冲刷收尾，`front::idle_tone_shift` 用它把梳定下来（原因与做法见该函数的文档注释）。
实测（干净合成信号）：

- MFSK 4 / 8 / 11 / 16 / 22 / 31 / 32 / 64 × `CQ CQ DE BG1AAA K ` / `TEST ` / `CQ ` × 15 个中心频率（900–1700 Hz）全对；
  MFSK 4 / 8 / 11 / 16 / 22 / 32 × 4 条报文（含 `73 `）× 35 个中心频率共 840 格全对；
- 下边带（频谱反转）与噪声幅度 1 / 2 / 3 的 MFSK16 / 8 各 9 个中心频率全对；
- 没有锚（录音从发射中途开始又没有冲刷）时沿用评分核对，与此前行为相同。

深度择优：两个深度的平均路径度量相差 8% 以上就以度量定胜负（干净信号正确深度 160–180、选错的 120–137，噪声幅度 3 下仍分得开），否则看可读性。
**真实的 gMFSK depth-10 录音这台机器上取不到**（用例 `#[ignore]`），只有合成的 `mfsk8_decodes_both_the_fldigi_and_the_gmfsk_interleaver_depth` 覆盖。

## 没覆盖什么

- 双向对拍只验了干净信号；弱信号 / 衰落下与 fldigi 接收机的差距只在上面的白噪声 / 载波差分对拍里量过。
- 漂移跟踪只用「fldigi 发端 → 本仓收端」一个方向验证，**没有**拿 fldigi 的接收机在同样的漂移录音上对比。
- 图片模式没有真实电台的录音，只有 fldigi 桌面版的合成录音。
